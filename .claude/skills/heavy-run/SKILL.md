# Тяжёлый прогон — под лизу

Машина одна, а сеансов на ней несколько (окна tmux, worktree).
Мутационный гейт, e2e и сборка бинарника съедают CPU и память целиком: два таких
прогона разом — это не «медленнее», а флаки, 30-секундные таймауты в случайных
файлах и OOM-kill. Поэтому тяжёлая команда берёт **слот ресурса** и отдаёт его,
когда закончила.

```bash
claude-lease run -- npm run test:mutation
```

**Скрипт-обёртка под манифест не попадает.** Ресурс лиза выбирает по подстроке командной строки
(`.claude/leases.json`: `npm run lint`, `npx stryker`, `npm run bench`…). Команда, спрятанная в
`.sh` из scratchpad (так обходят отказ изоляции worktree на env-префиксах), ни с чем не совпадает —
`claude-lease run -- bash gates.sh` запускается **без слота** и идёт параллельно с чужим и своим
Stryker'ом. Для скрипта называй ресурс явно: `claude-lease run -r машина -- bash gates.sh`. Так три
прогона одного сеанса (Stryker, бенч, линт) однажды шли разом, и цифры бенча пришлось снимать заново.

Мутационный гейт, e2e и покрытие **лучше гонять не здесь, а в CI** на своей ветке:
`npm run ci:run -- <static|test|mutation|e2e|e2e-windows|all>` (в фоне; код выхода — вердикт,
логи упавшего и артефакты — в `reports/ci/<run id>/`). Лиза ему не нужна, машина не голодает.
Подробно — [ниже](#гейт-в-ci-без-pr). Под лизу — то, что нужно
именно локально (узкий прогон, перепроверка вживлением, живой запуск бинаря).

Локальный `test:mutation` начинается с dry run'а всех связанных тестов. Если на машине красны
сьюты стоковых расширений из магазина (сеть, JDK, Go — свойство машины, а не ветки), Stryker
обрывается ещё в «initial test run». Тогда гоняй с `DIODE_E2E_OFFLINE=1` (такие сьюты
пропускаются, см. [TESTING.md](../../../docs/TESTING.md#тесты-на-стоковые-расширения--из-магазина-конвенция))
или бери вердикт из CI (`npm run ci:run -- mutation`) и укажи это в PR.

Команды `claude-lease` нет в PATH — значит машина без ограничений: запускай как
обычно, настраивать ничего не надо.

**Полный `npm run lint` — тоже под лизой:** соседний сеанс держал его 13 минут на 40–70% CPU и
трижды подряд свалил чужой мутационный гейт на dry run (`extension host subprocess did not become
ready in 5000ms` в случайных файлах); на дефолтной куче он ещё и OOM-ится.

**`npm run check:diff`, `npm run typecheck` и `npm test` — тоже под лизой** (с 2026-10-24, в манифесте,
хук не пустит без неё). Внутри `check:diff` — `tsc`, `eslint` и `vitest related`, на правке ядра это почти
весь граф тестов. Под на 7.5 ГБ без swap упал по памяти, когда разом шли `check:diff` одного сеанса,
`typecheck` второго и полный линт третьего — два из трёх были без лизы. Точечный
`npx vitest run <файл>` под лизу не берётся: гоняй его между правками свободно.

## Бенчи и перф-гейты — не здесь

`npm run bench:*` и `npm run test:perf*` (в том числе giant-file gate на `log500m`) **локально не
запускай** — ни под лизой, ни без неё. Они генерируют многосотмегабайтные фикстуры и меряют время,
а на машине, где рядом работают другие сеансы, цифры всё равно мусорные. Бюджеты проверяет CI
на PR. Нужна цифра для расследования — попроси человека, а не гоняй
бенч сам. Исключение — человек прямо попросил локальный бенч в этом сеансе.

## Гейт в CI без PR

Тяжёлый гейт можно прогнать не на своей машине, а на раннере GitHub — на своей ветке, без PR:

```bash
npm run ci:run -- mutation              # static | test | mutation | e2e | e2e-windows | all
npm run ci:run -- mutation --base <sha> # база диффа; по умолчанию merge-base с origin/main
npm run ci:run -- e2e --no-push         # ветка уже запушена (скрипт сверит remote с HEAD)
```

[`scripts/ci-run.mjs`](../../../scripts/ci-run.mjs) пушит ветку по https, запускает `ci.yml` вручную
(`workflow_dispatch`) только с выбранным гейтом, ждёт конца и **возвращает вердикт кодом выхода**:
0 — зелёный, 1 — красный, 2 — прогон не состоялся (push, dispatch). На провале печатает хвост логов
упавших шагов (включая шаги под `continue-on-error`); полные логи упавших job'ов и артефакты прогона
— отчёт Stryker (`mutation.json`, `.html`, лог) — ложатся в `reports/ci/<run id>/`.

Для мутационного гейта, e2e и покрытия это **предпочтительный путь**: лиза не нужна, соседние сеансы
не голодают, а раннер не страдает флаками от голода по CPU. Прогон идёт минуты (на 2 vCPU: static
~1.5 мин, test ~5.5, mutation инкрементально ~4.5, e2e ubuntu ~13.5, windows ~8, плюс `npm install`)
— запускай в фоне (`run_in_background`). Инкрементальный кэш Stryker'а у ручных прогонов свой, по
имени ветки: второй прогон той же ветки быстрее первого. `all` — то же, что гоняет PR, кроме
комментариев в PR: отчёты остаются в summary прогона.

**Короткое имя ветки.** Имя ветки попадает в статус-бар e2e-кадров (git-расширение). Длинное вроде
`worktree-agent-<hash>` выталкивает `Ln N, Col M` за правый край 100-колоночного кадра, и сценарии,
ждущие колонку (`inline-completion` — «Col 43»), краснеют по таймауту. Перед `ci:run` переименуй
ветку в короткую (`git branch -m fix/<тема>`) — под этим именем она всё равно пойдёт в PR.

## Ожидание слота: просто дай лизе висеть

Лиза встаёт в очередь и ждёт освобождения слота **столько, сколько нужно** — по
умолчанию без ограничения по времени. Впереди может идти сорокаминутный мутационный
гейт, а за ним ещё один: это нормальный рабочий режим, а не зависание.

Сторожить прогон не надо. Bash-инструмент на 120-й секунде команду не убивает, а
уводит в фон и будит тебя, когда она закончится; вывод остаётся в файле задачи.

```bash
claude-lease run -- npm run test:mutation      # так, и больше ничего не нужно
```

`run_in_background: true` — если не хочешь ждать ответа и займёшься чем-то ещё.
Код выхода команды пробрасывается как есть — гейт остаётся гейтом. Прервали прогон
(`TaskStop`, отмена) — лиза валит всю группу процессов прогона и только потом отдаёт
слот; недобитых Stryker'ов и воркеров после этого не остаётся.

## Не ставь -w, и не увидишь код 75

`-w <секунд>` означает «перестань ждать через столько-то и вернись с отказом». Отказ
— это **код 75** и строка «СЛОТ НЕ ПОЛУЧЕН». Читать её надо строго так: **прогон не
запускался**. Ни один тест не падал, ошибки в команде нет, чинить нечего — гейт просто
не выполнялся.

Поэтому `-w` без нужды не ставь: без него ожидание не обрывается и 75 не появляется.
Если 75 всё-таки пришёл — повтори тот же вызов без `-w` либо займись другой работой,
пока ресурс занят.

Чего **не** делать: править код «под красноту» — её нет; перезапускать в обход лизы
(`npx stryker`, `timeout 600 npm run …`); открывать второе окно, чтобы проскочить;
поднимать ёмкость машины под свою задачу. Занятый слот — не помеха, а причина, по
которой твой прогон не даст флак.

## Смерти, рестарты, зависшие держатели

Хартбитов и TTL здесь нет, и они не нужны: слот — это `flock`, его держит **ядро**,
пока жив процесс. Убили `-9`, сработал OOM-killer, перезапустился агент, ребутнулась
машина — блокировка снимается сама. Застрявшей лизы, которая «залочила всё к чертям»,
в этой схеме не бывает: залочить может только живой процесс.

Что всё-таки стоит проверить, если прогоны подозрительно ждут:

```bash
claude-lease status          # кто держит, сколько уже держит, чем занят, из какого каталога
claude-lease reap            # добить осиротевший прогон (обёртку убили -9, прогон остался)
claude-lease break машина    # намеренно снести зависшего держателя
```

- `status` отдельно помечает случай «слот свободен, но прошлый прогон осиротел и ест
  CPU». Следующий `claude-lease run` добивает такого сироту сам, до захвата слота, —
  двойного тяжёлого прогона не будет.
- Отставший фоновый процесс, который прогон оставил после себя, слот **не** держит:
  лиза не даёт дочерним процессам унаследовать блокировку. Так зависший демон не может
  запереть ресурс навсегда.
- Держатель висит час на пятиминутной задаче — это повод для `break`, а не для ожидания.
- Единственный случай, когда слот и правда не отпускается: держатель застрял в
  неубиваемом состоянии (`D`, зависший ввод-вывод). Он **жив**, поэтому его не берёт ни
  лиза, ни `kill -9` — но TTL тут сделал бы хуже: лиза «истекла» бы, второй прогон
  стартовал, а машину по-прежнему держал бы застрявший. Такое отдавай человеку.

## Что считается тяжёлым

Список — в [`.claude/leases.json`](../../leases.json) (`match`); он в гите и общий для
всех машин. Появился новый тяжёлый прогон — добавь его туда, в том же PR. Дешёвые
режимы вроде `npm run test:mutation -- --scope-only` вынесены в `except` и лизы не требуют.

## Чего в репозитории быть не должно

Ёмкости («сколько слотов на этой машине»), пути к самой лизе и настройки хуков —
свойство машины, не проекта: они живут в `~/.claude/` и в коммиты не попадают.
Просят «разрешить два прогона параллельно» — это правка одной строки в машинном файле
ёмкостей, а не этого манифеста.
