# Тяжёлый прогон — под лизу

Машина одна, а сеансов на ней несколько (окна tmux, worktree, офис агентов).
Мутационный гейт, e2e и сборка бинарника съедают CPU и память целиком: два таких
прогона разом — это не «медленнее», а флаки, 30-секундные таймауты в случайных
файлах и OOM-kill. Поэтому тяжёлая команда берёт **слот ресурса** и отдаёт его,
когда закончила.

```bash
claude-lease run -- npm run test:mutation
```

Команды `claude-lease` нет в PATH — значит машина без ограничений: запускай как
обычно, настраивать ничего не надо.

## Ожидание слота: просто дай лизе висеть

Лиза встаёт в очередь и ждёт освобождения слота **столько, сколько нужно** — по
умолчанию без ограничения по времени. Впереди может идти сорокаминутный мутационный
гейт, а за ним ещё один: это нормальный рабочий режим, а не зависание.

Сторожить прогон не надо. Bash-инструмент на 120-й секунде команду не убивает, а
уводит в фон и будит тебя, когда она закончится; вывод остаётся в файле задачи.

```bash
claude-lease run -- npm run test:mutation      # так, и больше ничего не нужно
```

`run_in_background: true` — если не хочешь ждать ответа и займёшься чем-то ещё.
Код выхода команды пробрасывается как есть — гейт остаётся гейтом. Прервали прогон
(`TaskStop`, отмена) — лиза валит всю группу процессов прогона и только потом отдаёт
слот; недобитых Stryker'ов и воркеров после этого не остаётся.

## Не ставь -w, и не увидишь код 75

`-w <секунд>` означает «перестань ждать через столько-то и вернись с отказом». Отказ
— это **код 75** и строка «СЛОТ НЕ ПОЛУЧЕН». Читать её надо строго так: **прогон не
запускался**. Ни один тест не падал, ошибки в команде нет, чинить нечего — гейт просто
не выполнялся.

Поэтому `-w` без нужды не ставь: без него ожидание не обрывается и 75 не появляется.
Если 75 всё-таки пришёл — повтори тот же вызов без `-w` либо займись другой работой,
пока ресурс занят.

Чего **не** делать: править код «под красноту» — её нет; перезапускать в обход лизы
(`npx stryker`, `timeout 600 npm run …`); открывать второе окно, чтобы проскочить;
поднимать ёмкость машины под свою задачу. Занятый слот — не помеха, а причина, по
которой твой прогон не даст флак.

## Смерти, рестарты, зависшие держатели

Хартбитов и TTL здесь нет, и они не нужны: слот — это `flock`, его держит **ядро**,
пока жив процесс. Убили `-9`, сработал OOM-killer, перезапустился агент, ребутнулась
машина — блокировка снимается сама. Застрявшей лизы, которая «залочила всё к чертям»,
в этой схеме не бывает: залочить может только живой процесс.

Что всё-таки стоит проверить, если прогоны подозрительно ждут:

```bash
claude-lease status          # кто держит, сколько уже держит, чем занят, из какого каталога
claude-lease reap            # добить осиротевший прогон (обёртку убили -9, прогон остался)
claude-lease break машина    # намеренно снести зависшего держателя
```

- `status` отдельно помечает случай «слот свободен, но прошлый прогон осиротел и ест
  CPU». Следующий `claude-lease run` добивает такого сироту сам, до захвата слота, —
  двойного тяжёлого прогона не будет.
- Отставший фоновый процесс, который прогон оставил после себя, слот **не** держит:
  лиза не даёт дочерним процессам унаследовать блокировку. Так зависший демон не может
  запереть ресурс навсегда.
- Держатель висит час на пятиминутной задаче — это повод для `break`, а не для ожидания.
- Единственный случай, когда слот и правда не отпускается: держатель застрял в
  неубиваемом состоянии (`D`, зависший ввод-вывод). Он **жив**, поэтому его не берёт ни
  лиза, ни `kill -9` — но TTL тут сделал бы хуже: лиза «истекла» бы, второй прогон
  стартовал, а машину по-прежнему держал бы застрявший. Такое отдавай человеку.

## Что считается тяжёлым

Список — в [`.claude/leases.json`](../../leases.json) (`match`); он в гите и общий для
всех машин. Появился новый тяжёлый прогон — добавь его туда, в том же PR. Дешёвые
режимы вроде `npm run test:mutation -- --scope-only` вынесены в `except` и лизы не требуют.

## Чего в репозитории быть не должно

Ёмкости («сколько слотов на этой машине»), пути к самой лизе и настройки хуков —
свойство машины, не проекта: они живут в `~/.claude/` и в коммиты не попадают.
Просят «разрешить два прогона параллельно» — это правка одной строки в машинном файле
ёмкостей, а не этого манифеста.
