# Спека вместо реализации

Человек хочет сосредоточиться на постановке задач, а делать их будет луп
([scripts/agent-loop/README.md](../../../scripts/agent-loop/README.md)). Твоя работа здесь — **не
писать код**, а подготовить issue, по которой реализатор и тестировщик справятся без вопросов:
у них человека нет, неясность для них — `returned`, то есть потерянный заход.

Код не правишь, worktree не заводишь, PR не открываешь. Разрешено: читать код и доки, запускать
приложение (`drive`), чтобы увидеть текущее поведение, смотреть эталон (`node scripts/vscode-ref.mjs`),
писать черновики в scratchpad.

## 1. Разобраться

- Что хочет человек — в терминах наблюдаемого результата. Непонятно — спроси сразу, вопросом с
  вариантами и дефолтом (AGENTS.md, «Как работать с человеком»).
- Как это сделано в эталоне vscode: форма фичи, настройки (ключи, дефолты, описания), команды,
  поведение на краях. Эталон — дефолт спеки; отступление называется отступлением и обосновывается.
- Где это живёт у нас: слои (docs/ARCHITECTURE.md), конкретные файлы `file:line`, соседние
  фичи, которые задача задевает, существующие тесты и e2e-сценарии рядом.
- Что уже есть в трекере (`docs/TODO/`) и в issues (`gh issue list --search …`), чтобы не
  поставить сделанное или поставленное.

## 2. Решить с человеком

Собери развилки и закрой их **до** оформления: каждая открытая развилка в issue — будущий
`returned`. Формулировка — вопрос, варианты с ценой, один дефолт. Решения записываются в issue
дословно, с датой.

## 3. Нарезать

Одна issue — один PR, который реализатор доводит за часы, а тестировщик проверяет за два.
Крупное — цепочка из 3–5 последовательных issues, каждая со своей наблюдаемой пользой и своим
критерием приёмки. Зависимость — нативное «Blocked by» GitHub плюс строка в теле; диспатчер не
возьмёт задачу, пока открыт хотя бы один блокер, и возьмёт сам, когда блокер закроется.

Параллельные задачи — без зависимости. Общий файл сам по себе — не повод для цепочки:
реализатор сливает `main` по ходу и перед вливанием (скилл `implementer`, «Синхронизация с
`main`»), а аддитивные правки — своя регистрация в списке, своя строка в таблице, свой парсер —
сливаются без конфликта. Цепочкой — когда одна задача **меняет** то, на что опирается другая
(новый метод сервиса, который следующая зовёт; переписанный участок, который следующая правит
снова; один и тот же компонент UI). Решение человека 2026-11-01: параллельность важнее
редких конфликтов — луп идёт в несколько слотов.

## 4. Оформить issue

Заголовок — коротко и по-русски (это issue, не PR). Тело по шаблону; лишние разделы убирай,
пустых не оставляй:

```markdown
## Цель
Что получит пользователь, одним абзацем. Как увидеть результат руками.

## Контекст
Где это живёт: `src/…/file.ts:120` — что там сейчас; причины, замеры, тупики, в которые уже сходили.

## Эталон
Как в vscode (файл/команда/настройка эталона). Отступления — явно, с причиной.

## Спека
Наблюдаемое поведение по пунктам — то, что тестировщик превратит в use cases: основной сценарий,
края (пусто, огромное, юникод, отмена, узкий терминал, темы), взаимодействие с соседними фичами.
Настройки: ключ, дефолт, scope, описание — дословно по эталону.

## Решения
2026-10-24: «…» — решение человека дословно.

## Границы
Что НЕ делать в этой задаче; какие соседние задачи этим занимаются.

## Как проверить
Подсказки тестировщику: сценарий-демо для `e2e/scenarios/`, что посмотреть в кадре, где лежат
соседние тесты.

Blocked by #123, #124
```

Баг — коротко: воспроизведение по шагам, ожидаемое и фактическое, где проявляется; метка `bug`.

```sh
gh issue create --title "<заголовок>" --body-file <файл> --label "ready to implement" [--label bug]
```

Зависимость, кроме строки `Blocked by` в теле, ставь нативно (так её видно в интерфейсе GitHub):

```sh
gh api repos/diode-editor/diode/issues/<N> --jq .id                      # числовой id блокера
gh api -X POST repos/diode-editor/diode/issues/<M>/dependencies/blocked_by -F issue_id=<id>
```

Задача, которую **пока нельзя** отдавать лупу (ждёт решения, не готова), — без метки
`ready to implement`; человек поставит её сам.

## 5. Итог

Список созданных issues со ссылками, порядок цепочки, что осталось решить человеку (если
осталось). Ничего не запускай: луп сам подберёт `ready to implement` на следующем тике.
