# Оркестратор: волна задач дочерними сессиями

Ты — родительская сессия. Код пишут дети, каждый в своём worktree. Каждый ребёнок доводит свой PR
до зелёного CI и вливает его сам (AGENTS.md, «Коммиты и PR»). Твоя работа: нарезать задачи, запускать,
следить, отвечать человеку и вовремя запускать следующую задачу.

## Запуск — только по явному «запускай»

Обсуждение плана — это ещё не старт (AGENTS.md, «Как работать с человеком»). Пока идёт разговор,
отвечай текстом и в конце спрашивай «запустить?».

## Перед запуском каждой задачи

1. **Не сделано ли уже?** Проверь `git log origin/main --oneline -30`, статус пункта в трекере
   и `gh pr list --state all --search <ключ>`. Запуск уже сделанной задачи человек ловил не раз:
   «Кажется это уже сделано! Закрой».
2. **Есть ли место.** По умолчанию держи не больше 4 детей сразу. Пятого можно добавить, если
   остальные просто ждут CI. Машина маленькая, параллельные vitest/e2e её душат. Перед запуском
   посмотри `cat /proc/loadavg`, `grep MemAvailable /proc/meminfo` и `claude-lease status`.
   Load5 около числа ядер или меньше 2,5 ГБ свободной памяти — подожди.
3. **Порядок.** Сначала понятные задачи, потом неясные. Неясные пусть спрашивают человека вопросом
   с вариантами и дефолтом. Задачи с общим файлом или зависимостью запускай по цепочке: следующую —
   после влития предыдущей.

## Handoff — короткий

Запускай через `/tmux-continue`. В промпт клади только то, чего нет в репозитории:

```
# Задача — результат и метрика
# Контекст из родительской сессии — file:line, причины, замеры, тупики
# Решения человека — дословно, с датой
# Границы — что НЕ делать; соседние задачи этой волны и их зоны (не трогать)
```

Правила проекта не пересказывай: свой PR вливать самому, гейты, лиза, сверка с эталоном,
drive, worktree и `git:wt-bootstrap`, обход изоляции worktree, публикация tuidom. Всё это есть
в AGENTS.md, ребёнок его прочтёт. Пересказ только устаревает. Попроси в конце написать итог:
номер PR, цифры, что осталось.

## Слежение

Монитор лежит рядом со скиллом. Он завершается с отчётом при первом событии: окно пропало,
окно простаивает (панель не меняется 4 проверки подряд), влит новый PR, закончились проверки
`WATCH_PR`, освободились ресурсы (`WAIT_FREE=<load5>`). Запускай его в фоне и жди уведомления:

```sh
python3 -I .claude/skills/orchestrate/monitor.py <ISO-время старта волны> <окно1> <окно2> …
```

На событие:
- **PR влит** — закрой окно ребёнка (`tmux-host-env tmux kill-window -t <окно>`), отметь задачу
  и запусти следующую, если есть место.
- **Окно простаивает** — прочитай хвост панели. Ребёнок ждёт ответа человека: перескажи вопрос
  человеку. Ждёт CI: ничего не делай. Застрял: подтолкни.
- **Сообщение ребёнку** — `tmux-host-env tmux send-keys -t <окно> -l '<текст>'`, затем отдельным
  вызовом `tmux-host-env tmux send-keys -t <окно> Enter`. Пиши, например, когда PR конфликтует
  с main («CONFLICTING — CI не запустится, перебазируйся») или упал флак («gh run rerun … --failed»).

## «Как дела?»

Отвечай по-русски, коротко, по каждой задаче: состояние, PR, что ждёт человека. Вопросы к
человеку ставь первыми. Это правило действует и после сжатия контекста.

## Машина перезагрузилась

Процессы сессий, фоновые шеллы, мониторы и лиза умерли, но транскрипты и worktree на месте.
Для каждого незавершённого ребёнка: найди id сессии (новейший `*.jsonl` в
`~/.claude/projects/<путь worktree с / → ->/` или в каталоге основного репо) и подними её в её
worktree:

```sh
tmux-host-env tmux new-window -d -n <слаг> -c <worktree> 'claude --resume <session-id> "Машина перезагрузилась: процесс сессии, фоновые шеллы, мониторы и лиза умерли. Проверь состояние (git, PR, CI, незавершённые прогоны) и продолжай с того места, где остановился."'
```

Потом заново запусти монитор.

## Мелочи волны

- Флаки, которые ловят дети, записываются в [список флаков](../../../docs/TODO/TestRunTime.md#флаки)
  прямо в `main`.
- Версию после волны выпускай только по просьбе человека ([docs/RELEASE.md](../../../docs/RELEASE.md)).
