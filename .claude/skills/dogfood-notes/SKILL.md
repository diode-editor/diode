# Заметки догфудинга → issues

Человек копит в своём списке короткие заметки по ходу работы в diode и вставляет их пачкой.
Твоя роль — диспетчер: сам ничего не исследуешь и issues не пишешь, это делают дочерние сессии
по скиллу [`spec`](../spec/SKILL.md). В конце у человека должно быть два результата: issues в
трекере и короткий список того, что вернулось к нему.

## 1. Разослать

1. `tmux-host-env` должен ответить кодом 0. Иначе работаем вне tmux: скажи об этом и остановись.
   Нагрузку проверь через `uptime`. Сессии `spec` лёгкие, сборок и тестов они не гоняют, поэтому
   ограничение «не больше ~4 разом» из `orchestrate` на них не распространяется. Десять окон —
   нормально.
2. На каждую заметку — слаг `spec-<тема>` и handoff-файл в scratchpad. Заметку перенеси
   **дословно**, с опечатками: по формулировке человека сессия поймёт, о чём он. От себя добавь
   только то, что нашёл за минуту `grep`/`find`: о каком файле речь, какой это репозиторий
   (diode, tuidom, скрипты лупа), какое имя у фичи в vscode. Если в пачке две похожие заметки,
   назови обеим сессиям окно соседки. Шаблон:

   ```markdown
   # Задача
   Через скилл /spec подготовить спеку и оформить GitHub issue(s) с меткой `ready to implement`
   по заметке человека: **<короткое название>**. Это не реализация.

   Заметка человека дословно:
   > <заметка>

   # Контекст из родительской сессии
   <подсказки: файлы, эталон, как воспроизвести через drive, соседние окна>
   Заметки разосланы пачкой, каждая в своей сессии. Непонятно — спрашивай человека, не додумывай.

   # Ограничения и договорённости
   - Результат — issue(s) по скиллу spec, код фичи не пишем.
   - Если окажется, что это уже работает или задача не нужна, сообщи человеку и issue не заводи.
   ```

3. Окна открывай с `-d`, чтобы tmux не перекидывал человека по всем окнам подряд:

   ```sh
   tmux-host-env tmux new-window -d -n "<slug>" -c <корень репо> "claude \"\$(cat <handoff>)\""
   ```

4. Отчёт: таблица «окно — заметка» и найденные пересечения. Вопросы сессии задают человеку
   сами в своих окнах.

## 2. Проверить и закрыть

Когда человек просит «проверь», «закрывай кто готов»:

- **Источник правды — трекер, а не текст в окне:**
  `gh issue list --state all --search "created:>=<сегодня>"`. Если заметка касалась tuidom,
  проверь ещё `-R tuidom/tuidom`.
- Хвост окна: `tmux-host-env tmux capture-pane -p -t <slug> -S -30`. Здесь есть ловушка. Текст в
  поле ввода `❯ …` после «done» может оказаться **подсказкой Claude Code**, которую никто не
  отправлял. Это не ответ человека и не сделанное действие. Пример: в окне стоит «да, оформи
  баг», а issue в трекере нет.
- Статус окна:
  - **готово** — issue заведены, или сессия доказала, что делать нечего, а человек согласился;
  - **ждёт человека** — открыт вопрос с вариантами, или сессия попросила данные;
  - **работает** — крутится `✻ …ing` или идёт `gh issue create`;
  - **не смогла / отменено** — человек сказал «отмена», баг не воспроизвёлся, причина вне
    diode (например, конфиг терминала).
- Закрывай через `tmux-host-env tmux kill-window -t <slug>` окна «готово» и «не смогла».
  «Ждёт» и «работает» не трогай, пока человек не скажет закрыть всё.
- Если одна сессия нашла что-то для другой, перешли ей сам, прежде чем закрывать:
  `tmux send-keys -t <slug> -l "<текст>"`, затем отдельно `send-keys -t <slug> Enter`.
  Хвост сессии, которую закрываешь, иначе пропадёт.

## 3. Вернуть человеку

Итог в два блока:

1. **Оформлено:** по строке на заметку — номера issues и цепочка (`#856 → #857`). Сюда же
   «делать нечего» с причиной в одну фразу. Если дочерние сессии коммитили доки прямо в main,
   назови хэши.
2. **Вернуть в список** — одним блоком ```` ``` ````, чтобы человек скопировал его к себе.
   Каждая строка — исходная заметка **дословно**. Под ней в скобках одна-две фразы находки:
   причина, обходной путь, кандидат в баг, который не оформили, путь `file:line`. Так при
   следующем заходе не придётся исследовать заново.

Если человек просит оформить что-то из возвращённого, делай сам по скиллу `spec`, без нового
окна. Находка уже лежит в разговоре.
