# Запуск ребёнка в сессии задачи

Сделано по образцу пользовательского скилла `tmux-continue`, но для автономной работы: окно
создаёт скрипт, промпт — не выжимка разговора, а вызов скилла роли, которому хватает номера issue.

```sh
node scripts/agent-loop/spawn.mjs --task <N> --role implementer|tester [--note <файл>]
```

Что делает скрипт:

- окно `<роль>` в сессии `task-<N>`, каталог — корень репозитория (ребёнок сам уйдёт в свой
  worktree по правилам проекта); отказ, если окно уже есть или сессии нет;
- команда окна — `claude --model $AGENT_LOOP_MODEL --permission-mode bypassPermissions "<промпт>"`:
  модель форсируется (дефолт `opus` — алиас последнего Opus), иначе на машине сработал бы её
  собственный `model`; без `bypassPermissions` ребёнок повис бы на первом неразрешённом `gh`;
- промпт `/<роль> <N>` плюс содержимое `--note`, записан в `<каталог задачи>/<роль>-prompt.md`
  и читается окном при старте — через кавычки командной строки текст не тащим;
- старый статус-файл роли удаляется, чтобы `wait.mjs` не прочитал прошлогодний;
- `AGENT_LOOP_TASK`, `AGENT_LOOP_MODEL`, `AGENT_LOOP_HOME` — в окружении окна;
- у окна фиксированный id сессии claude (`--session-id`), записан в `sessions.json` каталога
  задачи и уходит в issue вместе с возвратом (`return-task.mjs`). Задача возобновляется
  (`resume.json` от `start-task.mjs`): если прошлый прогон был на этой машине и транскрипт
  сессии роли на диске — окно стартует `claude --resume <id>` с тем же промптом плюс абзацем
  «Resumed task: …» (PR, причина возврата, вердикт тестировщика); иначе — свежая сессия с тем же
  абзацем. Менеджеру это неважно: команда одна и та же.

## Когда нужен `--note`

Только то, чего нет в issue и PR и что ребёнку надо знать с первой минуты. Тестировщику —
`note` реализатора из `implementer.json` (решения по неясностям спеки, сознательные отступления).
Правила проекта, гейты, лизу, worktree не пересказывай: это в AGENTS.md и в скилле роли.

Переключать человека в новое окно не надо — его тут нет, окно создаётся с `-d`.
