# Тик диспатчера

Ты — одноразовая сессия: делаешь один проход по правилам ниже и завершаешься. Ты ничего не
помнишь о прошлых тиках и не должен — всё состояние в GitHub (метки, комментарии), в tmux и в
`~/.claude/agent-loop/`. Устройство лупа — [scripts/agent-loop/README.md](../../../scripts/agent-loop/README.md).

Вопросов человеку не задаёшь: его здесь нет. Код не правишь, issues не комментируешь сам —
только через скрипты ниже. Решения принимаешь по фактам из `facts.mjs`, а действуешь скриптами:
они делают всё точно и одинаково.

## 0. Свежий main

```sh
git pull --ff-only
```

Не вышло из-за доступа (`Permission denied (publickey)`: человек отключился и ssh-агент пропал) —
репа публичная, бери по https:

```sh
git pull --ff-only https://github.com/diode-editor/diode.git main   # HTTPS_ORIGIN из lib.mjs
```

Не вышло и так (сеть, не fast-forward) — тик всё равно продолжай на том, что есть, и упомяни это в
выводе. Обновлённый скилл подхватит уже следующий тик.

## 1. Факты

```sh
node scripts/agent-loop/facts.mjs
```

В JSON: `machine` (нагрузка, память, лиза), `limits`, `verdict.canStart` с причинами, `sessions`
(живые `task-<N>`), `inProgress` (issues в работе: `sessionAlive`, `managerAlive`, `ageHours`,
`expired`, статусы ролей), `queue` (кандидаты по порядку: `bug` первыми, потом старые;
`branchExists`), `blocked` (issues с `ready to implement`, у которых открыт хотя бы один блокер —
нативное «Blocked by» GitHub или строка `Blocked by #N` в теле; в очередь не входят, их не
трогай — освободятся сами, когда блокер закроется), `worktrees`.

## 2. Свернуть то, что умерло

Для каждой issue из `inProgress`, одно из:

| Факт | Причина для `--reason` |
| --- | --- |
| `sessionAlive: false` | «сессия task-N не найдена — машина перезагрузилась или сессия убита; задача снята» |
| `expired: true` | «задача в работе дольше `limits.taskTimeoutHours` ч — снята по таймауту» |
| `sessionAlive: true`, `managerAlive: false`, окна детей есть | «окно менеджера пропало, дети остались без присмотра; задача снята» |

```sh
node scripts/agent-loop/return-task.mjs --task <N> --reason "<причина по-русски>"
```

Скрипт сам комментирует issue с хвостами панелей, переводит PR в draft, меняет метку на
`returned` и убивает сессию. Остальные задачи — живые, их ведёт менеджер, не трогай.

## 3. Уборка

```sh
node scripts/agent-loop/cleanup-worktrees.mjs
```

Сносит worktree с влитой веткой, где никто не работает, и ветки тестировщика влитых задач.
Что оставил и почему — печатает; этого достаточно, вручную ничего не досносить.

## 4. Взять одну задачу

Только если `verdict.canStart: true` и `queue` не пуста. Берёшь **первую** из `queue` — порядок
уже правильный. Одна задача за тик: следующий тик увидит нагрузку уже с ней.

```sh
node scripts/agent-loop/start-task.mjs --issue <N>
```

Коды выхода: `0` — запущена; `3` — отказ (ветка `issue/<N>` уже на origin — скрипт сам поставил
`returned` с объяснением; или issue не подходит) — возьми **следующую** из `queue`, но не больше
одной попытки сверх первой; `4` — задачу раньше захватил другой хост, это нормально, ничего не
делай; иначе — ошибка, напечатай и заверши тик.

`canStart: false` — напечатай причины и заверши тик. Пороги не обходить и не «подождать внутри
тика»: следующий тик через несколько минут.

## 5. Итог

Три-пять строк: что свернул, что снёс, что запустил (или почему нет). На этом всё.
