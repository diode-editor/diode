# Проектные хуки Claude Code

Подключены в [`.claude/settings.json`](../settings.json). Каждый — страховка от граблей, которые уже стоили
сессиям времени; ни один не ходит в сеть, каждый укладывается в ~50–100 мс, и любая собственная поломка
хука (битый JSON, нет git, чужой каталог) означает «пропустить», а не «запретить».

| Хук | Событие | Что ловит |
|---|---|---|
| `bash-guard.mjs` | PreToolUse(Bash) | `npm run test:mutation -- <ref>` — база гейта задаётся только `--base <ref>`, позиционный скрипт отвергает; хук отказывает до слота лизы; `git fetch <url> …:refs/remotes/…` без `--no-prune` — при `fetch.prune=true` удаляет остальные ref'ы; `git push` на ssh-remote — push только по https с `--force-with-lease=<ref>:<sha>` |
| `edit-guard.mjs` | PreToolUse(Edit\|Write\|NotebookEdit) | сессия в `.claude/worktrees/<имя>`, а правка целится в основной checkout или соседний worktree — подсказывает правильный путь |
| `stop-checklist.mjs` | Stop | мягкий чеклист «готово» по диффу ветки от `origin/main`: линт/типы не запускались в сессии, `feat` без сценария в `e2e/scenarios/`, `feat` без изменений в настройках (сверить с эталоном), `vscode.d.ts` без `docs/public/API-COVERAGE.md`. Каждый пункт — один раз (линт — на сессию, остальное — на ветку; состояние в `$(git rev-parse --git-dir)/claude-stop-checklist.json`), на `main` и без диффа молчит |

Отказ PreToolUse — `exit 2` и текст в stderr (он уходит модели). Stop-напоминание приходит модели
продолжением хода (`decision: block`) с явным разрешением закончить, если пункт неприменим; повторный
Stop в том же ходу (`stop_hook_active`) пропускается.

Лизу на тяжёлые прогоны проверяет отдельный глобальный хук (`~/.claude/settings.json`, см. скилл
`heavy-run`), здесь её нет.

## Изоляция worktree Claude Code (не наш хук)

Сессия, вошедшая в `.claude/worktrees/<имя>` (EnterWorktree), получает встроенную проверку самого
Claude Code. Это не хук из этого каталога, править тут нечего. Проверка отказывает Bash-команде,
если не может доказать, что та не выводит git за пределы worktree. Тексты отказа:
«command is too complex to verify», «This session is isolated in the worktree». По истории сессий
это самый частый отказ: сотни раз в большинстве worktree-сессий.

| Отказывается | Делай так |
|---|---|
| `$(…)`, переменные и функции оболочки, вычисляемые аргументы (`sed -n "$(…)p"`, циклы) | одна простая команда на вызов; цепочка `&&` из простых (prettier, vitest, grep) проходит |
| многострочная правка или выборка через heredoc `python3 -` вперемешку с другими командами | скрипт в scratchpad (инструмент Write) и один вызов `python3 -I <скрипт> <аргументы>` |
| `npm run git:push` / `git:pr-status` / `git:fetch` («npm с git среди операндов») | `node scripts/git/push.mjs <ветка>`, `node scripts/git/pr-status.mjs <PR>`, … |
| `cd <tuidom> && git …`, Bash-правки в соседнем checkout'е | `git -C <абсолютный путь> …`; правки там — инструментами Edit/Write; push tuidom — `git -C … push https://github.com/tuidom/tuidom.git <ref>` (`push origin` ловит ssh-предохранитель) |
| `npm run -s drive -- …` с переменными или функциями-обёртками | каждая команда drive — отдельным простым вызовом |
| команда с env-префиксом (`PATH=… claude-lease run …`) | короткий `.sh` в scratchpad, вызов `bash <скрипт>` |
| `gh pr create --body-file - <<EOF …`, если в тексте встречается «git» | тело — файлом в scratchpad (Write), `--body-file <путь>` |

Тесты: `node --test .claude/hooks/hooks.test.mjs`; в CI они идут в составе `npm run test:scripts`
(job `mutation`, шаг «Gate self-test»).

## Как хук читает команду — и на чём он уже ошибался

Ложный отказ хуже пропуска: он останавливает правильную команду и учит обходить хук. Оба правила ниже —
из таких отказов.

- **Смысл аргументов не угадываем — спрашиваем того, кто их разбирает.** Правило про `test:mutation`
  зовёт `parseArgs` из `scripts/mutation-gate.mjs` и отказывает только на его `PositionalArgumentError`.
  Своя копия логики знала лишь `--base`/`--since` и принимала за позиционный значение любого другого флага
  (`--testFiles <файл>`, `--concurrency 4`, `--verify-jobs 2`). Новый флаг гейта хук теперь понимает сам;
  прочие ошибки аргументов (`--base` без ревизии, `--verify-jobs x`) сообщает гейт — мгновенно, до Stryker'а.
- **Командную строку режет `simpleCommands` (`lib.mjs`), а не `split` по регулярке.** Она снимает кавычки
  и не режет по операторам внутри них; выбрасывает редиректы (`2>&1`, `> файл`, `&>лог`, `<<< строка`);
  `$(…)` и `` `…` `` оставляет одним непрозрачным словом; тело heredoc и `# комментарий` пропускает.
  Наивная резка давала и ложные отказы (`… 2>&1 | tail` — «позиционный `2>&1`»; `--base $(git merge-base …)`;
  текст команды в теле коммита или PR через heredoc), и пропуски (`git push 2>&1` на ssh-origin: `2>&1`
  читался как имя remote, и правило молчало). Команды внутри `$(…)`, heredoc и `bash -c "…"` хук
  не проверяет — это сознательный пропуск, а не отказ.
- Новое правило для Bash пиши поверх `simpleCommands` и клади в тесты не только голую команду, но и её же
  с `2>&1 | tail`, под `claude-lease run --` / `timeout 600` и в виде текста внутри кавычек и heredoc.
