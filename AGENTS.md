Diode — терминальный текстовый редактор (клон VS Code) на TypeScript/Node.js. Цели и неизменяемые ограничения — в GOAL.md, не забывай его читать.

# Карта документации
- GOAL.md — цели проекта и non-negotiable constraints
- docs/VISION.md — позиционирование: активы, ограничения реальности, направления, текущая ставка
- docs/ARCHITECTURE.md — концептуальная карта: слои и правила зависимостей (единственный источник правды по слоям). **Прочитай перед работой**; переносишь файлы, заводишь каталоги или меняешь зависимости слоёв — обнови его
- docs/arch/ — детальный справочник по слою на файл (Common, Editor, Extensions, Workbench, State, …); docs/DI.md — DI-контейнер
- TUIDom (движок TUI) — отдельный репозиторий [github.com/tuidom/tuidom](https://github.com/tuidom/tuidom), пакеты `@tuidom/*`; его доки живут там
- docs/TESTING.md — как тестировать каждый слой, e2e, приёмы отладки; docs/MUTATION.md — мутационный гейт (Stryker)
- docs/STYLE.md — идиомы под линт; docs/COMMITS.md — коммиты; docs/PR.md — что обязано быть в PR и влитие; docs/GIT.md — git-помощники, стек PR, уборка worktree; docs/RELEASE.md — выпуск версии
- docs/TODO/ — трекер задач (индекс — README.md); docs/public/ — публичные страницы для сайта (правила — в его README.md); packaging/README.md — каналы дистрибуции
- Скиллы `.claude/skills/`: `drive` (живой запуск), `heavy-run` (лиза на тяжёлые прогоны), `orchestrate` (волна дочерних сессий)

# Worktree
Задачу, начатую с планирования, ведём в отдельном worktree (EnterWorktree), если человек явно не сказал иначе. Worktree живут **только** в `.claude/worktrees/<имя>`. Сразу после входа — `npm run git:wt-bootstrap` (`node_modules` часто отстают от lock-файла, в том числе `@tuidom/*`). В итоге по задаче **всегда указывай полный путь к worktree** — человек оттуда запускает и проверяет.

# Хуки и изоляция
Проектные хуки (`.claude/hooks/`) и встроенная изоляция worktree Claude Code отказывают в части команд. Отказ — подсказка, как сделать правильно, а не повод обходить его другой командой. В worktree-сессии: одна простая команда на вызов, без `$(…)`, переменных и функций; многострочное — `python3 -I <скрипт из scratchpad>`; git-помощники — `node scripts/git/*.mjs`, а не `npm run git:*`; соседний checkout — `git -C <абсолютный путь>`. Таблица отказов → [.claude/hooks/README.md](.claude/hooks/README.md).

# Гейты и стиль
- Job `static` в CI — шесть проверок, любая красная блокирует PR; перед сдачей прогоняй все: `npm run typecheck`, `npm run lint` (тяжёлый — `claude-lease run -- npm run lint`, скилл `heavy-run`), `npm run valid-layers-check`, `npm run lazy-chunks-check`, `npm run cyrillic-check`, `npm run snapshot-check` (node ≥ 26.11). Формат и порядок импортов чинит `npm run lint:fix`.
- Между правками — `npm run check:diff` (только дифф ветки, десятки секунд); полных гейтов он не заменяет → [TESTING.md](docs/TESTING.md#быстрый-цикл-по-диффу-checkdiff). Спотыкается линт — [docs/STYLE.md](docs/STYLE.md).
- **Код — по-английски, доки — по-русски.** Комментарии, названия тестов и строки пишем по-английски, термины — по [глоссарию](docs/STYLE.md#глоссарий); `*.md`, `.claude/`, коммиты и PR — по-русски. Храповик — `npm run cyrillic-check` → [язык кода](docs/STYLE.md#язык-кода).
- Импорты — с расширением файла. Приватные члены — без подчёркивания, только модификатор.
- Имена файлов — **camelCase**, как у vscode, по главному экспорту (`menuRegistry.ts`). Тесты — колокацией и не одним огромным файлом: `tuiElement.test.ts`, `tuiElement.events.test.ts`.

# Коммиты, PR, релиз
- Коммиты — [docs/COMMITS.md](docs/COMMITS.md). Что обязано быть в PR — [docs/PR.md](docs/PR.md); фича с видимой частью приносит **сценарий-демо** в `e2e/scenarios/`.
- **Свой PR агент вливает сам** (squash) по зелёному CI, если человек не сказал иначе; красный CI доводит до зелёного. Флак вне диффа — `gh run rerun <run> --failed` и строка в [списке флаков](docs/TODO/TestFlakes.md#флаки) → [PR.md](docs/PR.md#зелёный-ci-и-влитие).
- Правки только доков (`docs/`, трекер, флаки) можно коммитить прямо в `main`. Версию выпускают только по просьбе человека → [docs/RELEASE.md](docs/RELEASE.md).

# Что считать «готово»
Урок #194/#195: фича бывает зелёной по тестам и покрытию и при этом не работать в приложении. Тест должен смотреть туда же, куда пользователь.
- **Покрытие — не сигнал DoD.** Храповик 100% слеп к ненаписанному: пропущенный продюсер события даёт 100% и нерабочую фичу.
- **Перед сдачей фичи — `npm run test:mutation`** (под лизой). Выжившего мутанта убиваем тестом или гасим `// Stryker disable next-line <мутатор>: причина`, но не ассертом ради балла. Фантомов руками не разоблачаем: гейт сам вживляет каждого выжившего и печатает класс → [таблица классов](docs/MUTATION.md#гейт-сам-перепроверяет-каждого-выжившего-вживлением).
- **Тестируй наблюдаемый результат, а не шов**, который только что написал: есть видимая часть — тест доходит до кадра.
- **На каждое новое RPC-сообщение — тест продюсера** («кто и по какому событию его шлёт»), не только разбора.
- **Фича поверх стокового расширения закрывается стоковым расширением** (настоящий `.vsix` из магазина) плюс герметичным тестом на синтетических → [конвенция](docs/TESTING.md#тесты-на-стоковые-расширения--из-магазина-конвенция).
- **Настройки — как в эталоне:** ключи, дефолты, `scope`, `enum`, описания дословно, в том же PR; неподдержанный ключ назван в PR → [Configuration.md](docs/arch/Configuration.md).
- **Запусти приложение.** Харнесс фейкает рендер и ввод — ровно там и живут баги. Перед «готово» — живой запуск и взгляд на кадр, скилл [`drive`](.claude/skills/drive/SKILL.md).
- **Выводы задачи — в репозиторий, а не в память агента.** Авто-память — только для фактов конкретной машины. Рецепты, грабли, устройство и решения человека — в AGENTS.md, docs/, скиллы или комментарии в том же PR.

# Как работать с человеком
- **Сначала эталон.** Форму фичи и устройство сверяй с vscode (`node scripts/vscode-ref.mjs` — исходники запинненного тега) **до** вопроса и до своей механики, эталонный вариант предлагай дефолтом. Чего нет в эталоне — отступление: так и называй и объясняй зачем. Найденные «наши отличия» почти всегда оказывались нормой эталона (урок #352: «тост забирает фокус» придумал агент).
- **Обсуждение — не команда.** Пока обсуждаем план — отвечай текстом и спрашивай «запустить?». «Можно пробовать» — согласие с идеей, не старт; работу и дочерние сессии начинай по явному «запускай/делай».
- **Пиши человеку по-русски** — статусы, итоги, и после сжатия контекста тоже.
- **Решение человека — вопросом с вариантами и дефолтом:** у каждого варианта цена, один дефолт, назван срок. Нет ответа к сроку — принят дефолт, и в PR это записано как решение по дедлайну.
- **Храповики не опускаем.** Планки покрытия, мутаций и прочих гейтов только растут. Массовая правка затянула старый долг — гейт пропускается разово по решению человека, долг уходит в трекер ([прецедент](docs/MUTATION.md#ограничение-о-котором-надо-знать)).

# Правила разработки
Сквозные конвенции; полные формулировки — по ссылкам.
- **Ограничения tuidom не обходим — чиним движок.** Правка — в репозитории tuidom (`TUIDOM_DIR`): своя ветка и PR, вливаешь сам. **Публикацию в npm запрашивай у человека** ([разрешил — рецепт](docs/RELEASE.md#tuidom)), до выхода версии diode на неё не завязывай; проверить заранее — `npm run engine:link`. Запрещено: копировать куски движка, monkey-patching, приватные поля (`as any`, `@ts-expect-error`), дубликат виджета ради хука, пост-обработка grid'а; тест-обходы — тоже обходы.
- **Цвета** — только имена токенов темы, никаких RGB-литералов и инлайн-фоллбэков; новый цвет — в `src/vs/platform/theme/common/colors/` → [Theme.md](docs/arch/Theme.md).
- **`vscode.d.ts` запиннен к upstream**: подняв поверхность, в том же PR обнови [API-COVERAGE.md](docs/public/API-COVERAGE.md); правило правки → [Extensions.md](docs/arch/Extensions.md).
- **Перенесённый код эталона** (баннер `//@diode:vendored`) руками не правится, только `npm run import:vscode-editor`; он 1-based, ядро 0-based, ±1 — только в адаптере → [ARCHITECTURE.md](docs/ARCHITECTURE.md#дословный-перенос-upstream-editorcommondiff).
- **DI** — токен `*DIToken` объявляется рядом со своим типом → [DI.md](docs/DI.md).
- **Состав фичи** — всё, что регистрирует `workbench/contrib/<f>/`, объявляется в её папке → [Workbench.md](docs/arch/Workbench.md#состав-фичи). **Команды** — id в стиле VS Code, доступность через typed when-контексты → [конвенции команд](docs/arch/workbench/Commands.md#конвенции-системы-команд).
- **Надёжность процесса:** дочерний процесс — только `GuardedChildProcess`; команда не роняет процесс; отказ host-обработчика RPC не бьёт по расширению; нет зависимости — null-объект → [Common.md](docs/arch/Common.md#надёжность-процесса-что-не-должно-его-ронять).
- **Верхний уровень модулей — без окружения** (бинарь стартует из V8-снапшота, собранного на CI): на уровне модуля не читать `process.env`/`argv`/`cwd`/терминал, не звать `Date.now`/`Math.random`, не создавать таймеры, `Intl.*`, сокеты → [Common.md](docs/arch/Common.md#верхний-уровень-модулей-и-v8-снапшот).
- **Поднятый таймаут — признак непонятой причины.** Сначала выясни, почему медленно; таймаут «чтобы прошло» прячет гонку.
