# Стиль кода: идиомы под линт

Линт (`strictTypeChecked` + `stylisticTypeChecked` typescript-eslint) и типы — гейт CI, job `static`. Здесь — не правила (их держит сам линт), а выходы из ситуаций, на которых спотыкались: линт говорит «что не так», этот файл — «как правильно».

## Чтение по индексу

Правило `no-unnecessary-condition` часто ругается на защитные проверки чтения по индексу: `noUncheckedIndexedAccess` в `tsconfig.json` выключен (включение даёт ~2700 ошибок типов — отдельная задача), поэтому `arr[i]` для TS всегда непустой. Не выбрасывай проверку — сделай её честной:

- `.at(i)` там, где индекс неотрицательный (у `.at(-1)` семантика другая — отсчёт с конца!);
- `Partial<Record<…>>` для справочников с произвольным ключом;
- явная проверка границ там, где индекс бывает отрицательным.

## Идиомы под `strictTypeChecked`

- `no-non-null-assertion` и `non-nullable-type-assertion-style` противоречат друг другу (одно запрещает `!`, другое требует его вместо каста) — выход не `!` и не каст, а настоящее сужение: инвариант типом, уже проверенное значение параметром, `?.()`.
- `no-unsafe-enum-comparison` между нашим рантайм-enum и `vscode.*` из типов (разные номинальные типы) — `(a as number) === (B.X as number)`.
- Строку в символы — `Array.from(str)`, а не `[...str]` (`no-misused-spread`).
- Необязательный объект в условии — `if (keys?.evaluate(expr) !== true)`, а не `keys !== undefined && …`: TS сужает по такому сравнению, а мёртвой ветки для покрытия и мутаций нет.
- Zero-width space из upstream-джсдоков (невидимый символ между `**` и `/*.js` в `vscode.d.ts`) в нашем коде краснит `no-irregular-whitespace` — пиши `**\/*.js`, как в `glob.ts`.

## Сгенерированный код

Генератор форматирует свой вывод тем же prettier, что и линт (образцы — `scripts/generate-settings-schema.mjs`, `scripts/import-codicons.mjs`), иначе `lint:fix` и генератор переписывают файл друг за другом. Конфликт сгенерированного файла при ребейзе руками не разрешают: берут версию `main` и перегенерируют (`settings-schema.generated.ts` — `npm run build:extensions`).

## Комментарии

Комментарий пишется только там, где код сам этого не скажет. Читатель видит имя, тип и тело — пересказывать их не нужно. Проверка: без этого комментария грамотный читатель **ошибётся** или **«починит» код обратно**? Нет — комментарий не нужен. Хочется объяснить, что делает код, — сначала попробуй имя: константа вместо магического числа, говорящий параметр вместо `ti`/`qi`.

**Оставляем:**
- «почему», а не «что»: причину неочевидного решения, отвергнутую альтернативу («не `split+pop`, потому что…»);
- инварианты и контракты, которые не выражены типом: единицы, базис координат (0-/1-based), кто владеет и кто освобождает, допустимый порядок вызовов;
- обходы и хаки — с причиной и условием, когда их можно снять;
- соответствие эталону vscode (`// как ExtHostFoo._bar`) и уроки с номером PR/issue (`#194`), объясняющие, зачем здесь проверка;
- причины, продиктованные линтом, производительностью, V8-снапшотом, покрытием и мутациями;
- `TODO`/`FIXME` и служебные маркеры (`Stryker disable`, `c8 ignore`, `eslint-disable`, `@deprecated`, `@diode:*`) — их не трогают никогда.

**Удаляем:**
- пересказ имени, типа или сигнатуры (`/** Имя файла. */ name: string`), JSDoc, повторяющий параметры;
- описание следующей строки (`// создаём map`, `// возвращаем результат`);
- историю правок (`раньше было…`, `как у прежнего провайдера`) — она живёт в git;
- разделители секций и закомментированный код;
- «рекламу»: зачем класс появился и что он заменил (`вместо IDisposable[] с ручным циклом`) — это повод для PR, а не инструкция читателю;
- сравнения с эталоном, которые ничего не защищают (`у upstream такого класса нет`), и пересказ правил проекта и языка (`register без подчёркивания — правило AGENTS.md`);
- контракт, который уже сказан именем (`deleteAndLeak` — «дальше отвечает вызывающий»).

Исключение — шимы `//@diode:shim`: английские комментарии upstream в них остаются, чтобы файл сверялся с оригиналом глазами.

Длинный комментарий, где «почему» тонет в пересказе, ужимаем до этого «почему».

Массовую чистку проверяет `node scripts/check-comments-only.mjs [база]`: поток токенов кода без комментариев до и после совпадает (пробелы, переносы и висячие запятые, которые prettier убирает при схлопывании литерала, не считаются), служебные маркеры на месте (маркер считается только в начале строки комментария — упоминание в прозе можно ужимать), дословные копии upstream не тронуты.

## Язык кода

Код — по-английски: комментарии, названия тестов (`it`/`describe`/`bench`, описания в `until(…)`), строки (ошибки, логи, сообщения CLI и UI). По-английски и всё, что уходит в историю и релизы: сообщения коммитов (заголовок и тело) и PR (заголовок и описание) → [COMMITS.md](COMMITS.md). Доки остаются по-русски: `*.md` (docs/, AGENTS.md, GOAL.md), `.claude/` целиком (скиллы, хуки, агенты).

- **Храповик** `npm run cyrillic-check` (job `static`): у каждого файла вне доков (и у публичных страниц `docs/public/`, кроме README) число строк с кириллицей только падает, база — `scripts/cyrillic-baseline.json`, нового файла в ней нет — значит ноль. Перевёл — `npm run cyrillic-check -- --update` опускает базу (поднять её команда не может).
- **Ссылка на русский якорь дока** (`docs/STYLE.md#комментарии`) кириллицей не считается — так и пишем.
- **Нарочная кириллица** (тест юникода, кириллический ввод): в коде — `\u`-escape с латинской транскрипцией рядом (`"\u0451" // "yo"`); новая фикстура-файл — строка в базе руками, причина — в PR. Сейчас в базе только такие: `e2e/fixtures/completion-cyrillic.txt` (дополнение по кириллическим словам) и `e2e/fixtures/ghost-cancel-sample.txt` (демо `inlineCompletionCancel`: без латиницы попапу автодополнения по словам не из чего открыться).
- **Строка UI, которая есть в vscode,** — дословно её английский текст из эталона (`node scripts/vscode-ref.mjs`).
- **Заголовок PR** проверяет workflow `PR title` (`scripts/check-pr-title.mjs`): кириллица в заголовке — красный, переименуй PR. Описание PR и коммиты проверяются только правилом: цитата решения человека по-русски в описании допустима, если она помечена как цитата.
- **Перевод комментариев** проверяет `node scripts/check-comments-only.mjs [база] --no-cyrillic`: вдобавок к обычному гейту в комментариях изменённых файлов не осталось кириллицы.
- **Переводим смысл, а не слова:** английский — как в комментариях vscode, коротко и в настоящем времени. Правила [комментариев](#комментарии) действуют и тут: пересказ, найденный при переводе, удаляем, а не переводим.
