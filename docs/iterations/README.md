# Итерации

Работа офиса агентов идёт итерациями. Итерация — это ветка `iteration/NN` (фактически dev-ветка) и её
журнал `NN.md` рядом с этим файлом. Заявки ложатся в ветку по одной, вливанием, а в конце итерации
собираются в один PR в `main` со ссылкой на сборку.

Журнал итерации ведут роли офиса, руками его не правят: он живёт на самой ветке итерации, и из него
собирается тело PR. Формат — таблица, по строке на заявку:

| Узел | Заявка | Ветка | Влито | Статус |
| --- | --- | --- | --- | --- |
| n-7 | дерево файлов показывает git-статус | `task/n-7` | `a1b2c3d` | влито |
| n-9 | пикер тем по Ctrl+K Ctrl+T | `task/n-9` | `e4f5a6b` | отозвано |

`отозвано` — человек не принял эту заявку при приёмке PR: её вливание отменено (`revert`), сама заявка
уехала к аналитику на доработку, а PR пересобран без неё.

Механика — [`scripts/iteration.mjs`](../../scripts/iteration.mjs), процесс целиком —
[`office/README.md`](../../office/README.md).

Рядом с журналом итерации живёт её ретроспектива — `NN-ретро.md`: на чём человек возвращал работу,
что он писал в замечаниях и какие обращения к нему стоит снять или сузить. Её пишет роль «ретроспектива»
после того, как итерация влита.
