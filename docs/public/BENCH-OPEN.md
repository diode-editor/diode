# Бенчмарк открытия файла

Цифры живут не здесь: их раз в неделю снимает CI-джоба
[`bench.yml`](../../.github/workflows/bench.yml) (`npm run bench:open` на собранном SEA-бинаре,
shared runner GitHub Actions) и кладёт в ветку данных
[`bench-data`](https://github.com/diode-editor/diode/tree/bench-data/open):
сырой JSON каждого прогона, `latest.json`/`latest.md` и индекс. Страница сайта
[diode-editor.github.io/benchmarks](https://diode-editor.github.io/benchmarks/) читает эту ветку и
показывает последний прогон и историю по неделям. Руками цифры не пишутся ни сюда, ни туда.

## Что меряется

Настоящий бинарь запускается в PTY 120×32 в герметичном окружении (свой user-data-dir и HOME),
отсчёт — от спауна процесса, момент появления текста и подсветки восстанавливается по таймстемпам
чанков stdout. Матрица — от 100 строк до 200 000 строк (13 МБ) TypeScript; полугигабайтный
plaintext-лог вернётся в матрицу вместе со стримингом (сейчас он открывается за полторы минуты и
умирает на первой правке). LSP в замер не входит: замер заканчивается на TextMate-подсветке.

- **Наших мс** — главная цифра: до текста минус пол node. Пол — `node -e ""`, спаунится тем же
  способом (PTY), то есть минимальный процесс, который вообще исполняет JS. `node --version` полом
  служить не может — современный node отвечает на него до подъёма V8; он печатается для справки.
- **Над полом бинаря** — минус `diode --version`: убирает ещё и парс SEA-бандла, остаётся кухня
  воркбенча.
- **До текста / до подсветки** — от спауна до кадра с текстом файла и до кадра, где ключевое слово
  раскрашено темой.
- **Лестница вех** — белый ящик: `performance.mark` внутри процесса (`DIODE_STARTUP_TRACE`),
  от старта процесса через конфиг, workbench, чтение файла и документ до кадра с текстом и подъёма
  extension host'а; рядом печатается расхождение с чёрным ящиком.
- **Латентность клавиши** после открытия — вставка символа в середине файла, Enter, undo,
  `Ctrl+End`, поиск слова: от записи в PTY до кадра, где изменение видно.
- **Peak RSS** — `VmHWM` процесса редактора за весь прогон.
- **Шум** — медиана и IQR по прогонам; строка помечается «шумно» при IQR > 20 % медианы.
  Первый прогон каждого размера — прогревочный, в статистике не участвует.

## Защита цифр

Бюджет кухни старта закреплён перф-гейтом `e2e/bench/startupBudget.bench.ts` (`npm run test:perf`):
медиана «наших мс» на `small` не выше `STARTUP_BUDGET_OURS_MS`. Бюджет — храповик: снижается по
мере оптимизаций, ослабляется только с замером. План работ — [docs/TODO/OpenPerformance.md](../TODO/OpenPerformance.md).

Локальный прогон: `npm run bench:open -- --sizes=small,medium,xlarge --runs=5 --label="условия"`;
положить его в ту же ветку данных рядом с CI-шными можно скриптом `scripts/bench-publish.mjs`.
