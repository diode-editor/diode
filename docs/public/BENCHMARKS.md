# Бенчмарки: скорость старта

> **Заготовка.** Структура страницы готова, цифры сравнительной таблицы ещё не сняты по методике
> ниже. Предварительные числа лестницы — с одной машины автора; перед публикацией пересним всё
> одним прогоном и уберём эту плашку.

diode написан на TypeScript и работает на Node.js — для терминального редактора это принято считать
приговором по скорости. Эта страница существует, чтобы спор шёл о цифрах, а не об ощущениях. Каждое
число здесь воспроизводимо по методике внизу и защищено перф-тестом в CI.

## Лестница старта

Старт — это не одно число, а лестница: ничего медленного не стоит на пути к первому кадру
(ровно так устроен и сам VS Code).

| веха | median |
| --- | ---: |
| пол Node (`node --version`) | 77 мс |
| первый кадр (workbench виден) | 87 мс |
| редактор готов (текст с подсветкой) | 103 мс |

Ключевое число здесь — не 103, а **26**: столько стоит весь наш workbench поверх пола рантайма
(77 мс — цена самого `node`, до первого кадра — 10 мс наших). Extension host поднимается лениво уже
после первого кадра; language server приезжает асинхронно ещё позже. 103 мс — под порогом
восприятия, а по ssh старт целиком тонет в сетевом RTT.

## Методика

_Заполнить при снятии цифр одним прогоном:_

- **Железо и условия:** модель CPU, режим питания (Balanced), от батареи или от сети, ОС.
- **Что считаем стартом:** для diode — вехи лестницы (инструментированы в коде); для остальных —
  до готовности принять ввод (описать способ фиксации для каждого редактора).
- **Как мерили:** N прогонов, медиана; тёплый/холодный кэш; точные команды запуска каждого
  редактора — списком, чтобы любой мог повторить.

## Защита цифр

Число, которым хвастаемся, обязано быть защищено тестом: перф-бюджет старта закреплён в CI
(`vitest.perf.config.ts`, `npm run test:perf`) — фичи будут откусывать миллисекунды по чуть-чуть,
и без храповика 26 мс превратились бы в 200 незаметно.
