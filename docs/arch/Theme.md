# Theme

Часть архитектуры Diode — обзорная карта в [../ARCHITECTURE.md](../ARCHITECTURE.md).

Система темизации, совместимая с VS Code theme files. Активная тема — `WorkbenchTheme` за `ThemeService` (`ThemeServiceDIToken`), хранит packed RGB/RGBA + правила подсветки синтаксиса. Доставка в виджеты — одна точка: `applyThemeVars(root, theme)` кладёт палитру в корневой var-scope TUIDom (подписан WorkbenchComponent), дальше цвета расходятся каскадом токенов ([STYLES.md (tuidom)](https://github.com/tuidom/tuidom/blob/main/docs/STYLES.md)); TUIDom про темы так и не знает — он знает про переменные. Хостовые мосты в `computeThemeVars` — единственное место, где словарь отличается от палитры темы: `menuBar.* ← titleBar.active*` (строка меню — собственные токены tuidom, в темах VS Code ключа нет: с кастомным заголовком меню рисуется на цветах titleBar, у которых у нас дефолты VS Code `#3C3C3C`/`#DDDDDD`) и `menu.border ← menu.separatorBackground`, когда рамка меню после наложения на `menu.background` неотличима от него (разница каналов меньше 8): темы вроде Catppuccin задают `menu.border` цветом фона меню и отделяют меню тенью `box-shadow`, которой в TUI нет, а меню того же цвета, что редактор, без рамки растворяется в нём — цвет разделителя пунктов в той же теме заведомо виден.

> **Правило работы с цветами (единственная система цветов).** Все цвета UI берутся **только** из активной темы через `theme.getColor(key)` / `theme.getRequiredColor(key)`. Никаких цветовых литералов в контроллерах/виджетах и никаких инлайн-фоллбэков. Цвета, которых нет в JSON-темах VS Code (они из code-based color registry), задают наши определения цветов — `platform/theme/common/colors/*.ts` (группы по областям + явный merge `COLOR_CONTRIBUTIONS` в `colorContributions.ts`; механика — `ColorRegistry.ts`, аналог `registerColor` из `vs/platform/theme/common/colorRegistry.ts`). Новый цвет добавляется **в одном месте**: определение `{ defaults: { dark, light }, description }` в группе своей области — из него деривируются и типизация ключа (`WorkbenchColorKey`), и таблица дефолтов. Исключение — widget-baseline константы для элементов без темизируемого ключа VS Code.

Enforcement и разрешение цветов:
- `getColor(key) → number | undefined` (опциональные цвета потребитель обрабатывает сам); `getRequiredColor(key) → number` — **кидает**, если цвета нет ни в теме, ни в дефолтах. То есть используемый required-цвет обязан иметь дефолт (покрытие проверяет `colors/colorContributions.test.ts`); genuinely-опциональные ключи объявляются с `defaults: null`.
- `WorkbenchTheme.fromThemeFile(json)` слоит дефолты **под** цвета темы (тема побеждает) и парсит hex→packRgb. Дефолт может быть **ссылкой на другой ключ** (`"quickInput.background": { dark: "editorWidget.background", … }` — как `registerColor(id, editorWidgetBackground)` у VS Code): ссылка разрешается по уже слитой таблице, так что тема, задавшая базовый ключ, получает и производные (Catppuccin задаёт `editorWidget.background`, и пикер, hover, уведомления красятся им; меню наследует `dropdown.*`, выделение — `list.activeSelection*`). Так же `terminal.background` → `panel.background` (в VS Code дефолта нет, терминал в панели рисуется её фоном): тема без цветов терминала не получает тёмный прямоугольник посреди панели; `terminal.foreground` — свой hex, как у VS Code. 16 ANSI-цветов `terminal.ansi*` и режим цветов хост-терминала — не var-scope, а палитра сессии (`TerminalColorsService`, [workbench/Terminal.md](workbench/Terminal.md#цвета)). Ссылка на незарегистрированный ключ или цикл — ошибка определения, инвариант держит `colorContributions.test.ts`. Выражений над цветами (`transparent(ref, 0.2)`) по-прежнему нет — такие дефолты запекаются hex-ом.
- **Альфа.** С tuidom 0.4.0 цвет с альфой — штатное число (`packRgba`; `parseHexColor` в `colorUtils.ts` делегирует движку и только требует ведущий `#`): палитра и `tokenColors` уходят в var-scope с альфой как есть, композитинг выполняет движок в порядке отрисовки (грид — патч bg на то, что уже нарисовано в ячейке; каскад — собственный bg элемента на унаследованный; [STYLES.md, «Модель цвета»](https://github.com/tuidom/tuidom/blob/main/docs/STYLES.md)). Отсюда правило для painter'ов: заливший область и пишущий поверх текст передаёт в `drawText`/`setCell` **непрозрачный** bg (`resolvedStyle.bg`, либо токен, один раз скомпозиченный `compositeOver` с фоном элемента — так делает редактор с фоном декорированной строки и зоны), иначе полупрозрачный токен ляжет двумя слоями. Дефолты в определениях цветов по-прежнему пишутся hex-строкой (выражений над цветами нет), но альфа в них допустима; `editor.selectionBackground` получил дефолты VS Code (`#264F78`/`#ADD6FF`), и выделение красится токеном темы (у Catppuccin — `#9399b240` поверх фона строки).
- `ThemeRegistry` (`ThemeRegistryDIToken`) — реестр тем по label, `resolve`/`list`/`unregister`. Встроенные сидируются первыми; темы расширений (`contributes.themes`) регистрирует `ExtensionThemeContributor` (`workbench/services/extensions/common/`) — на старте, **все и до первого кадра**: файл темы читается через `IAssetAccess`, разбирается `themeFileParser.ts` (JSONC; невалидные цвета и правила — warning и пропуск; `semanticTokenColors` разбирается в упорядоченный `semanticTokenRules`, `semanticHighlighting` — только булевым; `tokenColors` строкой / `.tmTheme` — не поддержано, подсветка дефолтная), цепочка `include` резолвится относительно файла и сливается `mergeThemeFiles.ts` (colors — object-merge, tokenColors и `semanticTokenRules` — конкатенация base-first, `semanticHighlighting` — OR по цепочке; та же семантика, что у `scripts/import-vscode-themes.mjs`), `uiTheme` → `type`, ключ — `label` из манифеста. Коллизии label — последняя регистрация побеждает (встроенные → builtin-расширения → пользовательские), warning в лог. Решения — [ниже](#темы-расширений-решения).
- `themes/` — встроенные темы, импортированы **verbatim** из microsoft/vscode и **разреженные**: неопределённые цвета приходят из определений `platform/theme/common/colors/`, поэтому дописывать их руками не нужно (перезатрётся при ре-импорте).

```
IThemeFile (JSON, 1:1 c VS Code)
   │  scripts/import-vscode-themes.mjs (verbatim из microsoft/vscode)
   ▼
themes/*.ts ──▶ ThemeRegistry (label → IThemeFile) ──▶ resolve(label) ──▶ WorkbenchTheme
                    ▲                                                          │
   contributes.themes расширений (ExtensionThemeContributor, на старте) ────────│
                                                                               │
   workbench.colorTheme / preferred*ColorTheme ──▶ выбор активной ──▶ ThemeService ──┤ onThemeChange
   (по схеме терминала: HostColorSchemeService)                                │
                                                                               ▼
                              WorkbenchComponent: applyThemeVars → корневой var-scope → каскад
```

Выбор темы: `main.ts` — после сканирования расширений и `await contributor.apply()` — читает `workbench.colorTheme` → `ThemeRegistry.resolve` (неизвестное имя, в том числе тема ещё не установленного расширения, → `DEFAULT_COLOR_THEME` с warning в лог `extensions`; настройка не переписывается). Поэтому первый кадр уже в теме расширения, без промежуточного Dark Modern. Рантайм-смена — команда `workbench.action.selectTheme`: quick-pick с **live preview**, Enter применяет и persist'ит через `IConfigurationService.updateValue`, Escape откатывает.

### Тема по схеме терминала (`window.autoDetectColorScheme`)

Как у эталона: при включённой настройке активную тему называет не `workbench.colorTheme`, а `workbench.preferredDarkColorTheme` / `workbench.preferredLightColorTheme` — по схеме хоста. Выбор ключа — `getColorThemeSettingId` (`services/themes/common/themeConfiguration.ts`, аналог `ThemeConfiguration.getColorThemeSettingId`). Им пользуются все три места, которые читают или пишут тему: `main.ts` (первый кадр), `ThemeConfigContribution` (смена любого из трёх ключей, самой настройки и схемы хоста) и пикер (Enter пишет в ключ текущей схемы, как `setColorTheme` эталона: выбранный в тёмном режиме Catppuccin Frappé становится тёмной темой, светлая не трогается). Парную тему diode не угадывает — пользователь один раз выбирает тему в каждом режиме.

«Системная схема» у нас — **схема терминала**: TUI не может спросить ОС, и по ssh это всё равно терминал пользователя, а не ОС удалённой машины. Её ведёт `HostColorSchemeService` (`services/themes/browser/`, аналог `IHostColorSchemeService`). Источников два, оба через `ITerminalBackend` tuidom:

- **отчёты режима 2031** (`onColorSchemeChange`: Ghostty, kitty, Contour, tmux ≥ 3.6) — ответ на запрос при старте и сообщение при каждой смене. Так тема переключается на лету, когда ОС сменила оформление, а тема терминала следует за ней;
- **яркость фона OSC 11** (`probeHostColors`, относительная яркость меньше середины — тёмная) — один раз, для терминалов без 2031. Отчёт 2031 главнее догадки по фону, даже пришедший позже.

Запросы уходят не раньше фазы `restored` (tty уже в raw-режиме, иначе ответ эхом лёг бы на экран) и только при включённой настройке: с выключенной diode в терминал ничего нового не шлёт. Терминал без обоих протоколов, а также терминал с зафиксированной темой (не следующей за ОС) — схема не меняется. Последняя схема хранится в состоянии (`LAST_HOST_COLOR_SCHEME`, scope `application`): первый кадр рисуется до ответа терминала, и без неё светлый терминал стартовал бы в тёмной теме и через мгновение перекрашивался. Схема ни разу не известна (первый запуск, терминал молчит) — `workbench.colorTheme`, как с выключенной настройкой (отступление: у эталона схема ОС известна всегда). Не поддержано: `window.autoDetectHighContrast` и пара high-contrast тем — терминал о контрасте не сообщает; периодический опрос OSC 11 для терминалов без 2031. Демо — `e2e/scenarios/autoDetectColorScheme.scenario.ts` (смену схемы в headless шлёт метод инспектора `Diode.setHostColorScheme`).

### Темы расширений: решения

Тема из магазина проходит тот же путь, что любое расширение: установка → `Reload Window` → тема в пикере и в `workbench.colorTheme`, формат — VS Code, стоковые темы с open-vsx работают без правок (#84; смоук магазина — Catppuccin).

1. **Ключ — `label` из манифеста**, не `name` внутри JSON: так `workbench.colorTheme`, перенесённый из VS Code, совпадает с нашим. Тема без `label` или `path` — пропуск с записью в лог.
2. **Файлы тем читаются на старте, все и до первого кадра.** Файл темы — десятки КБ (грамматики ленивые, потому что их мегабайты), а пикеру нужен синхронный `resolve` на каждую стрелку. Заодно нет «мигания»: тема расширения из настроек — уже в первом кадре, hot-swap при поздней регистрации не нужен, потому что поздней регистрации нет.
3. **Порядок в `main.ts`: сканирование расширений → регистрация тем → выбор активной.**
4. **Коллизии label** — последняя регистрация побеждает (встроенные → builtin-расширения → пользовательские), warning в лог.
5. **Пропавшая тема — откат на дефолт, настройку не трогаем**: поставил расширение обратно — тема вернулась без действий (как у VS Code).
6. **`include` — в рантайме** относительно файла темы через `IAssetAccess` того же расширения; цикл или отсутствующий include — тема пропускается. `mergeThemeFiles` повторяет семантику импорт-скрипта, на это тест.
7. **`uiTheme` → `type`**: `vs` → `light`, `vs-dark` → `dark`, `hc-black` → `hc`, `hc-light` → `hcLight`; нет или неизвестен — `dark` с warning.
8. **`tokenColors` строкой (`.tmTheme`, plist) не поддержан**: тема регистрируется с цветами workbench и дефолтной подсветкой, warning в лог. Современные темы держат правила inline; plist-парсер — если такая тема попросится в реестр.

### Иконки: Nerd Font или Unicode (`diode.icons.nerdFont`)

Иконки рисуются глифами Nerd Font из Private Use Area — в шрифте без них это «тофу». Узнать шрифт нельзя: терминал не сообщает, какие глифы у него есть, а ширину для CPR берёт из таблицы wcwidth, а не из шрифта. Поэтому — настройка `diode.icons.nerdFont` (`auto | on | off`, `scope: application`, регистрируется рядом с `keyboard.platform`). `auto` выключает глифы только на консоли Linux (`TERM=linux`), остальное — `on` (решение человека 2026-10-24: в неизвестном терминале без регрессии). Отступление от эталона: у vscode шрифт кодиконов свой, ближайшее — `workbench.productIconTheme` и `workbench.iconTheme: null`; `off` у нас — встроенная «Unicode»-тема продуктовых иконок плюс «No file icons».

- **Таблицы — в `base/common`**: `codicons.generated.ts` (имя → глиф Nerd Font) и `codiconsUnicode.ts` (имя → один символ BMP вне PUA шириной 1, без эмодзи и вариационных селекторов; имени нет — пусто). Иконка по месту — `IProductIcon { nerdFont, unicode }` (`codicons.ts`): `codicon("refresh")` либо литерал, где глиф не кодикон (шевроны заголовков вью — nf-fa, ветка — nf-dev). Инварианты таблицы и покрытие её символов шрифтами растеризатора проверяют `codicons.test.ts` и `e2e/helpers/renderScreenshot.test.ts`.
- **Режим — одна точка правды, `ProductIconService`** (`platform/theme/common/productIconService.ts`, `ProductIconServiceDIToken`): `nerdFont`, `glyph(icon)`, `codicon(name)`, `renderCodicons(text)` для `$(name)` расширений, `fileIcon(name)` — `undefined` в `off`, и потребитель убирает колонку иконки вместе с пробелом. `$TERM` сервис получает из `terminalEnvironmentModule` (модуль верхнего уровня окружение не читает — снапшот). Код вне DI и тесты берут `NERD_FONT_ICONS` — неизменный набор Nerd Font.
- **Смена на лету**: `onDidChange` — каждый, кто запёк глиф в отрисовку, перерисовывается сам: дерево Explorer и Problems (`refresh`), деревья расширений (`ExtensionTreeView` перестраивает строки из последних ответов, не спрашивая подпроцесс), вкладки, заголовки вью (`ViewsService` → `setNerdFont` шапок, кнопки — повторный резолв меню: `MenuRegistry` резолвит `icon` пункта на каждый вызов), шевроны фолдинга (`TextEditorConfiguration` → `EditorElement.nerdFont`), ветка и счётчик задач в статус-баре, элементы статус-бара расширений (перерисовываются из сырого текста), прогресс (на каждом кадре спиннера), SCM, терминал. Строки, которые расширение регистрирует один раз — заголовки команд палитры из манифеста, имя канала OUTPUT, — и одноразовые quick pick / тосты берут режим на момент создания.
- **Глифы внутри виджетов tuidom** (шевроны `TreeViewElement`/`ListViewElement`, замок read-only вкладки, иконки видов автодополнения) — глиф-токены движка (`GLYPH_TOKEN_DEFAULTS` в `@tuidom/core/dom/glyphTokens`, дефолт — Nerd Font). `platform/theme/browser/widgetGlyphs.ts` кладёт таблицу в корень workbench через `setGlyphs`, как палитру через `setStyleVars`: в `on` — `null` (дефолты движка), в `off` — те же кодиконы через `ProductIconService` (`chevron-down`/`chevron-right`, `lock` — как у закреплённой группы, виды автодополнения — `symbol-*`, как `CompletionItemKinds.toIcon` эталона). Таблица каскадирует на всё дерево, включая оверлеи; смена настройки — повторный `setGlyphs`, дерево перерисовывается.

Не входит: `iconThemes`/`productIconThemes` (иконок файлов нет), горячее появление темы без перезагрузки окна, `workbench.colorCustomizations`. Тень оверлеев (`widget.shadow`, tuidom 0.5.0) объявлена цветом, но у оверлеев не включена — включать точечно (`shadow: true` в опциях сессии).

**Зависимости:** Theme → Rendering (ColorUtils/packRgb), Common. Находится на одном уровне с Workbench.
