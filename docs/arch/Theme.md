# Theme/

Часть архитектуры Diode — обзорная карта в [../ARCHITECTURE.md](../ARCHITECTURE.md).

Система темизации, совместимая с VS Code theme files. Активная тема — `WorkbenchTheme` за `ThemeService` (`ThemeServiceDIToken`), хранит packed RGB/RGBA + правила подсветки синтаксиса. Доставка в виджеты — одна точка: `applyThemeVars(root, theme)` кладёт палитру в корневой var-scope TUIDom (подписан WorkbenchComponent), дальше цвета расходятся каскадом токенов ([STYLES.md (tuidom)](https://github.com/tuidom/tuidom/blob/main/docs/STYLES.md)); TUIDom про темы так и не знает — он знает про переменные. Хостовые мосты в `computeThemeVars` — единственное место, где словарь отличается от палитры темы: `terminal.background ← panel.background`, `terminal.foreground ← editor.foreground` (для тем без цветов терминала; 16 ANSI-цветов `terminal.ansi*` и режим цветов хост-терминала — не var-scope, а палитра сессии: `TerminalColorsService`, docs/TODO/IntegratedTerminal.md) `menuBar.* ← titleBar.active*` (строка меню — собственные токены tuidom, в темах VS Code ключа нет: с кастомным заголовком меню рисуется на цветах titleBar, у которых у нас дефолты VS Code `#3C3C3C`/`#DDDDDD`) и `menu.border ← menu.separatorBackground`, когда рамка меню после наложения на `menu.background` неотличима от него (разница каналов меньше 8): темы вроде Catppuccin задают `menu.border` цветом фона меню и отделяют меню тенью `box-shadow`, которой в TUI нет, а меню того же цвета, что редактор, без рамки растворяется в нём — цвет разделителя пунктов в той же теме заведомо виден.

> **Правило работы с цветами (единственная система цветов).** Все цвета UI берутся **только** из активной темы через `theme.getColor(key)` / `theme.getRequiredColor(key)`. Никаких цветовых литералов в контроллерах/виджетах и никаких инлайн-фоллбэков. Цвета, которых нет в JSON-темах VS Code (они из code-based color registry), задают наши определения цветов — `Theme/colors/*.ts` (группы по областям + явный merge `COLOR_CONTRIBUTIONS` в `colorContributions.ts`; механика — `ColorRegistry.ts`, аналог `registerColor` из `vs/platform/theme/common/colorRegistry.ts`). Новый цвет добавляется **в одном месте**: определение `{ defaults: { dark, light }, description }` в группе своей области — из него деривируются и типизация ключа (`WorkbenchColorKey`), и таблица дефолтов. Исключение — widget-baseline константы для элементов без темизируемого ключа VS Code.

Enforcement и разрешение цветов:
- `getColor(key) → number | undefined` (опциональные цвета потребитель обрабатывает сам); `getRequiredColor(key) → number` — **кидает**, если цвета нет ни в теме, ни в дефолтах. То есть используемый required-цвет обязан иметь дефолт (покрытие проверяет `colors/colorContributions.test.ts`); genuinely-опциональные ключи объявляются с `defaults: null`.
- `WorkbenchTheme.fromThemeFile(json)` слоит дефолты **под** цвета темы (тема побеждает) и парсит hex→packRgb. Дефолт может быть **ссылкой на другой ключ** (`"quickInput.background": { dark: "editorWidget.background", … }` — как `registerColor(id, editorWidgetBackground)` у VS Code): ссылка разрешается по уже слитой таблице, так что тема, задавшая базовый ключ, получает и производные (Catppuccin задаёт `editorWidget.background`, и пикер, hover, уведомления красятся им; меню наследует `dropdown.*`, выделение — `list.activeSelection*`). Ссылка на незарегистрированный ключ или цикл — ошибка определения, инвариант держит `colorContributions.test.ts`. Выражений над цветами (`transparent(ref, 0.2)`) по-прежнему нет — такие дефолты запекаются hex-ом.
- **Альфа.** С tuidom 0.4.0 цвет с альфой — штатное число (`packRgba`; `parseHexColor` в `colorUtils.ts` делегирует движку и только требует ведущий `#`): палитра и `tokenColors` уходят в var-scope с альфой как есть, композитинг выполняет движок в порядке отрисовки (грид — патч bg на то, что уже нарисовано в ячейке; каскад — собственный bg элемента на унаследованный; [STYLES.md, «Модель цвета»](https://github.com/tuidom/tuidom/blob/main/docs/STYLES.md)). Отсюда правило для painter'ов: заливший область и пишущий поверх текст передаёт в `drawText`/`setCell` **непрозрачный** bg (`resolvedStyle.bg`, либо токен, один раз скомпозиченный `compositeOver` с фоном элемента — так делает редактор с фоном декорированной строки и зоны), иначе полупрозрачный токен ляжет двумя слоями. Дефолты в определениях цветов по-прежнему пишутся hex-строкой (выражений над цветами нет), но альфа в них допустима; `editor.selectionBackground` получил дефолты VS Code (`#264F78`/`#ADD6FF`), и выделение красится токеном темы (у Catppuccin — `#9399b240` поверх фона строки).
- `ThemeRegistry` (`ThemeRegistryDIToken`) — реестр тем по label, `resolve`/`list`/`unregister`. Встроенные сидируются первыми; темы расширений (`contributes.themes`) регистрирует `ExtensionThemeContributor` (`workbench/services/extensions/common/`) — на старте, **все и до первого кадра**: файл темы читается через `IAssetAccess`, разбирается `themeFileParser.ts` (JSONC; невалидные цвета и правила — warning и пропуск; `semanticTokenColors` разбирается в упорядоченный `semanticTokenRules`, `semanticHighlighting` — только булевым; `tokenColors` строкой / `.tmTheme` — не поддержано, подсветка дефолтная), цепочка `include` резолвится относительно файла и сливается `mergeThemeFiles.ts` (colors — object-merge, tokenColors и `semanticTokenRules` — конкатенация base-first, `semanticHighlighting` — OR по цепочке; та же семантика, что у `scripts/import-vscode-themes.mjs`), `uiTheme` → `type`, ключ — `label` из манифеста. Коллизии label — последняя регистрация побеждает (встроенные → builtin-расширения → пользовательские), warning в лог. Постановка и чек-лист — [../TODO/Theming.md](../TODO/Theming.md).
- `themes/` — встроенные темы, импортированы **verbatim** из microsoft/vscode и **разреженные**: неопределённые цвета приходят из определений `Theme/colors/`, поэтому дописывать их руками не нужно (перезатрётся при ре-импорте).

Выбор темы: `main.ts` — после сканирования расширений и `await contributor.apply()` — читает `workbench.colorTheme` → `ThemeRegistry.resolve` (неизвестное имя, в том числе тема ещё не установленного расширения, → `DEFAULT_COLOR_THEME` с warning в лог `extensions`; настройка не переписывается). Поэтому первый кадр уже в теме расширения, без промежуточного Dark Modern. Рантайм-смена — команда `workbench.action.selectTheme`: quick-pick с **live preview**, Enter применяет и persist'ит через `IConfigurationService.updateValue`, Escape откатывает.

**Зависимости:** Theme → Rendering (ColorUtils/packRgb), Common. Находится на одном уровне с Workbench.
