# Два списочных контрола: TreeViewElement (data-driven) и ListViewElement (DOM-строки)

Статус: `[~]` — зафиксированное решение + техдолг. Возник после миграции поиска (#210)
и Source Control на `ListViewElement`.

## Решение (осознанное, не временное)

В tuidom живут **два** списочных контрола, и это намеренно:

- **`TreeViewElement<T>`** (`ui/tree/`) — data-driven: потребитель отдаёт
  `ITreeDataProvider` (`getChildren`/`getTreeItem`/`getKey`), дерево само рисует строки из
  `ITreeItem { label, collapsible, badge, labelColor }`. **Остаётся**, потому что внешнее
  API расширений устроено так же: vscode `window.createTreeView` + `TreeDataProvider` —
  data-driven контракт, и когда мы раскомментируем этот неймспейс в `vscode.d.ts`,
  `TreeViewElement` станет его прямым исполнителем без переходников. Продовый потребитель
  сегодня — Explorer (плюс ленивая подгрузка каталогов, которой у списка нет).
- **`ListViewElement`** (`ui/list/`) — виртуализирующий контейнер с настоящими
  TUIElement-строками: богатая строка = композиция обычных элементов (посимвольная
  подсветка, инлайн-кнопки через делегацию кликов), без расширения интерфейсов виджета.
  Для собственных списков workbench: результаты поиска, Changes.

Выбор для нового списка: данные приходят провайдером/из расширения → tree; строка требует
собственной вёрстки/интерактива → list. Оба O(видимого) по кадру — производительность не
критерий выбора.

## Техдолг (цена двух реализаций)

- [ ] **Дублирование общих механик**: курсор/мультивыбор/клавиатура/typeahead/hover/
      ensureVisible реализованы в обоих контролах близнецами (list копировал tree).
      Возможное сближение — общий внутренний «selection model»-модуль или реализация
      `TreeViewElement` как data-driven фасада поверх `ListViewElement` (провайдер →
      фабрика строк); браться только при следующей содержательной правке этих механик,
      не ради симметрии.
- [ ] **Union-instanceof по месту стыка с workbench**: ключ `listFocus`
      (`workbenchContextKeys.ts`) и команды `list.*` (`listActions.ts`) перечисляют оба
      класса руками. Третий списочный контрол — сигнал завести общий интерфейс.
- [ ] **QuickPick/CompletionList** рисуют свои списки сами (custom draw) — кандидаты на
      `ListViewElement`, отдельными заходами и только при реальной необходимости
      (баг/фича в их списках).
