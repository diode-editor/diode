# Extensions view — просмотр магазина и установка из UI

Цель: дать пользователю поставить расширение **из редактора**, не выходя в CLI. К началу
задачи магазин был доступен только командой `--install-extension <id>`: клиент умел всё
(HTTP-источник, резолв версии, sha256, установка, удаление, список установленных), но
у этого не было ни одной точки входа в UI. Просмотр уже сделан (раздел «Статус» ниже),
установка кнопкой — следующий шаг.

Минимум шага: найти расширение → посмотреть, что это → поставить → увидеть, что оно
установлено → уметь удалить. Всё сверх этого (рейтинги, категории, сортировки,
рекомендации, авто-обновление) — вне шага.

Связанные документы: [Marketplace.md](Marketplace.md) (реестр, формат, источники —
шаги 1–3 сделаны), [Extensions.md](Extensions.md) (рантайм расширений; Phase 7 —
lifecycle и reload, Phase 8b — вклады `views`), [docs/arch/Workbench.md](../arch/Workbench.md)
(ViewsService/SidebarService, шов `IEditorPane`), [docs/arch/Extensions.md](../arch/Extensions.md).

---

## Что уже готово в коде (шов, на который ложится view)

Ничего из перечисленного писать заново не нужно — задача в том, чтобы дать этому UI.

- `createRegistrySource(spec, onProblem)` (`platform/extensionManagement/node/`) —
  HTTP или файловый источник, дефолт — публичный реестр `DEFAULT_REGISTRY_URL`.
- `IExtensionRegistrySource.getIndex()/getMeta(id)/fetchArtifact(version, tempDir)`.
- `searchRegistryIndex(index, query)` (`common/registryFormat.ts`) — подстрочный поиск по
  `id`/`displayName`/`description`; пустой запрос отдаёт полный список.
- `isVersionCompatible` / `resolveCompatibleVersion` (`common/resolveCompatibleVersion.ts`) —
  матчинг `engines.diode`/`engines.vscode` против версий сборки.
- `installFromRegistry(source, id, { extensionsDir, host, version? })` — мета → версия →
  артефакт → sha256 → распаковка, с откатом при id-mismatch. Возвращает
  `{ id, version, previous }`; предыдущие версии того же id **сносятся** — то есть
  «обновление» это та же установка.
- `listInstalledExtensions(extensionsDir)` → `{ id, version, dir }[]`,
  `uninstallExtension(id, extensionsDir)` → `{ removed }`.
- `EditorService.openPane(pane)` + `IEditorPane` — шов для нефайловой вкладки
  (идентичность по `uri`: повторное открытие переключает на существующую вкладку).
  Прецедент — `DiffEditorPane2` со схемой `diff:`.
- `ViewsService.registerContainer/registerView/setViewBody` + `SidebarService` —
  вьюлет сайдбара; ближайший прототип UI («строка ввода сверху + список снизу») —
  `contrib/search/browser/searchComponent.ts`.
- `ProgressService` (`platform/progress/`) + `ViewProgressContribution` — индикатор
  работы в заголовке view.

## Принятые решения

Согласовано с пользователем перед началом; каждое сужает объём шага.

1. **Раскладка — как в VS Code: вьюлет сайдбара + страница расширения во вкладке.**
   Activity bar'а у нас нет, поэтому показ вьюлета — команда `workbench.view.extensions`
   (конвенция `workbench.view.*`, как Explorer/Search/SCM).
2. **После установки — перезагрузка окна, а не горячая активация.** Расширения
   сканируются один раз на старте (`scanExtensions` в `main.ts`), горячей перезагрузки
   вкладов нет (Extensions.md, Phase 7). Врать про «уже работает» нельзя, поэтому UI
   даёт кнопку `Reload Window`: процесс поднимается заново с теми же аргументами,
   сессия восстанавливается, вклад начинает работать. Перезагружает пользователь —
   сам, когда готов потерять текущее состояние сессии.
3. **Страница расширения — шапка + кнопки + `meta.readme` обычным текстом.**
   Markdown-рендерера в проекте нет, и заводить его в этом шаге не будем: разметка
   видна как есть, перенос строк по ширине.
4. **Каталог — кэш в памяти на сессию + явный Refresh.** Дисковый кэш с TTL и
   оффлайн-режим (показ последнего известного индекса) — отдельная задача, заводится
   вместе со своей инвалидацией.

## Статус: сделано

Первый срез закрыл «найти и посмотреть» (US-1…US-10, US-18…US-21), второй — установку,
удаление и перезагрузку окна (US-11…US-17). Ниже — что и где живёт.

- `IExtensionsWorkbenchService` (`contrib/extensions/common/extensionsWorkbench.ts`) — контракт и
  DI-токен; реализация в `node/` (сеть через источник + чтение каталога расширений). Разделение не
  косметическое: вьюлет из `browser/` иначе импортировал бы `node/`, и это потребовало бы записи в
  список исключений `scripts/check-layers.mjs`.
- Карточка (`IExtensionListEntry`) — слияние записи индекса с установленным на диске; состояние
  (`available`/`installed`/`outdated`/`incompatible`) считается по `latest.engines` и версиям.
  Установленное **не из магазина** тоже карточка: поля берутся из его манифеста
  (`listInstalledExtensions` теперь отдаёт `displayName`/`description`).
- Каталог кэшируется в памяти: первый фетч — при первом показе вьюлета (`focus`), дальше фильтрация
  локальная, обновление — команда `extensions.refresh` (кнопка в заголовке секции, прогресс через
  `ProgressService`). На старте приложение в сеть не ходит.
- Пока каталог читается, список говорит `Loading extensions…`: пустой список на медленной сети
  иначе читался бы как «магазин пуст».
- Сетевой сбой не бросается в UI: карточки установленного остаются, а в секции магазина появляется
  строка `Retry — <причина>`; её активация повторяет запрос.
- Вьюлет `EXTENSIONS` (`browser/extensionsComponent.ts`) — строка поиска + список из двух групп;
  раскладка «шапка + тело» вынесена из Search в общий `HeaderBodyViewElement`. Команды —
  `workbench.view.extensions` (`Ctrl+Shift+X`, плюс аккорд `Ctrl+K X` для legacy-терминалов) и
  `extensions.refresh`.
- Страница расширения — `IEditorPane` с ресурсом `extension:<id>`: идентичность вкладки даёт
  `EditorService.openPane` бесплатно (повторное открытие переключает, а не плодит). Содержимое —
  чистые функции `buildExtensionHeaderLines`/`buildExtensionBodyLines` + свой перенос по словам
  (`wrapText`): wrap-элемента в tuidom нет, а `TextBlockElement` — блок фиксированных строк.
  Перенос пересчитывается прямо в раскладке при смене ширины, поэтому первый же кадр вкладки полный.
- Кнопки страницы — настоящие `ButtonElement` в закреплённой шапке; их состав считает чистая
  `describeExtensionButtons` (`Install` / `Update to X.Y.Z` + `Uninstall` / выключенный `Install`
  у несовместимого / `Reload Window` после операции). Клавиатура — приём модальных диалогов:
  стрелки ходят по ряду, `Tab` уводит в readme и обратно; глобальные бинды не мешают, у страницы
  нет текстового фокуса. Фокус вкладки встаёт на первую доступную кнопку — в том числе на
  `Reload Window` сразу после установки.
- Установка/удаление — `ExtensionPageActions` (`browser/extensionPageActions.ts`): прогресс
  (`ProgressService`, локация `window` — процентов у загрузки артефакта нет), транзиентное
  сообщение в статус-баре (общий `showTransientNotice`) и перезагрузка окна **командой**
  `workbench.action.reloadWindow` — тем же путём, что палитра и меню, включая вопрос о
  несохранённых вкладках.
- Перезагрузка окна — `base/node/restartProcess.ts`: процесс поднимается заново с теми же
  аргументами, состояние сессии пишется на диск до старта нового окна. Первый reload делает
  текущий процесс супервизором (`spawnSync` со `stdio: "inherit"`), дальнейшие обслуживает он —
  терминал не отбирается, процессы не копятся (см. [docs/arch/Workbench.md](../arch/Workbench.md)).
- Ошибка установки (несовместимость, битый sha256, недоступный реестр) — значение, а не
  исключение: текст приезжает в шапку страницы, кнопка снова доступна, на диске пусто.
- Тесты: юниты рядом с кодом (сервис на фейковом источнике и tmp-каталоге, чистые функции разметки
  и кнопок, компоненты через кадр) и герметичные e2e против настоящего бинаря —
  `e2e/extensionsView.functional.test.ts` (просмотр) и `e2e/extensionsInstall.functional.test.ts`
  (установка, обновление, удаление и перезагрузка окна на настоящих `.vsix`) — см.
  [TESTING.md](../TESTING.md).

## Пользовательские сценарии

Приёмочный чек-лист: при реализации каждый закрывается тестом (e2e — против
**локального файлового** реестра-фикстуры, чтобы прогон был герметичен; сетевой прогон
магазина уже есть отдельно — `e2e/marketplace/`), после — ручная проверка по списку.

### Просмотр и поиск

- **US-1. Открыть магазин.** → `Ctrl+Shift+X` (либо палитра → «Extensions: Show
  Extensions»). → Сайдбар раскрыт, показан вьюлет `EXTENSIONS`, фокус в строке поиска;
  под ней секция каталога со всеми записями реестра (`id`, displayName, версия, краткое
  описание) и секция `INSTALLED` с установленными.
- **US-2. Найти по слову.** Открыт вьюлет. → Набрать `editor`. → Список каталога
  фильтруется по мере ввода **локально** (`searchRegistryIndex`, без обращений в сеть);
  секция `INSTALLED` фильтруется тем же запросом.
- **US-3. Ничего не найдено.** → Набрать `zzzz`. → Вместо списка — «No extensions found»;
  очистка строки возвращает полный каталог.
- **US-4. Видно, что уже стоит.** Установлено `test.tab-setter`. → Открыть вьюлет. →
  Запись есть в `INSTALLED` с версией, и в каталоге та же запись помечена `Installed`.
- **US-5. Видно, что есть обновление.** Установлено `test.tab-setter@0.0.1`, в реестре
  `0.0.2`. → Открыть вьюлет. → Запись помечена `Update available 0.0.2` (в каталоге и в
  `INSTALLED`).
- **US-6. Видно несовместимое.** В реестре запись, у которой ни одна версия не проходит
  `engines` текущей сборки. → Открыть вьюлет. → Запись помечена `Incompatible`.
- **US-7. Клавиатура целиком.** → `Tab` из строки поиска уводит фокус в список, стрелки
  двигают выделение по обеим секциям, `Enter` открывает страницу, `Shift+Tab` возвращает
  в строку поиска. Мышь — эквивалент (клик = выделение, двойной клик/Enter = страница).

### Страница расширения

- **US-8. Открыть страницу.** Выделена запись каталога. → `Enter`. → Открылась вкладка с
  меткой расширения (`EditorConfig`), в ней: displayName, `publisher.name`, версия,
  `kind`, требуемые `engines`, ссылка на репозиторий, статус (`Installed` /
  `Not installed` / `Incompatible`), кнопки и ниже — текст `meta.readme` с переносом по
  ширине и прокруткой.
- **US-9. Повторное открытие не плодит вкладки.** Страница `EditorConfig` открыта, фокус
  в редакторе. → Открыть её же из вьюлета. → Активируется существующая вкладка, вторая
  не появляется (идентичность вкладки — `uri` вида `extension:<id>`).
- **US-10. Страница расширения, которого нет в магазине.** Установлено расширение
  вручную (`--install-extension foo.vsix`), в реестре его нет. → Открыть из `INSTALLED`. →
  Страница построена из локального манифеста (id, версия, описание), readme нет,
  доступна только кнопка `Uninstall`.

### Установка и удаление

- **US-11. Установить.** Страница не установленного расширения. → Нажать `Install`. →
  На время работы — индикатор прогресса и погашенные кнопки; по завершении: статус
  `Installed`, появилась кнопка `Uninstall`, запись есть в секции `INSTALLED` (с бейджем
  `Reload`), а первой кнопкой стоит `Reload Window` — на неё же встаёт фокус. В статус-баре —
  «Installed <id>@<version> — reload window to activate».
- **US-12. Расширение реально установлено на диск.** После US-11. → Проверить
  `<user-data-dir>/extensions`. → Каталог `<id>-<version>` с распакованным
  `package.json`; `--list-extensions` показывает ту же пару id@version.
- **US-13. Расширение работает после перезагрузки окна.** После US-11 поставлено
  `test.sample-lang`, открыт `sample.diodesample`. → Нажать `Reload Window`. → Окно
  поднялось заново с той же сессией, и в статус-баре язык `Diode Sample` (то есть вклад
  приехал, а не только байты). Та же команда доступна из палитры и меню File.
- **US-14. Обновить установленное.** Установлена версия старее реестровой (US-5). →
  Нажать `Update to X.Y.Z` (это та же установка). → Стоит новая версия, старый каталог
  снесён (`listInstalledExtensions` показывает ровно одну), появилось приглашение
  перезагрузить окно.
- **US-15. Удалить.** Страница установленного расширения. → Нажать `Uninstall`. →
  Каталог(и) расширения удалены, статус `Not installed`, запись ушла из `INSTALLED`,
  сообщение «Uninstalled <id> — reload window to apply».
- **US-16. Несовместимое не ставится.** Страница записи с `Incompatible`. → Кнопка
  `Install` есть, но выключена (фокус её не берёт), а рядом — почему: строка статуса
  `Incompatible with this build of Diode` и требование записи (`Requires: vscode ^99.0.0`).
- **US-17. Ошибка установки не оставляет мусора.** Реестр отдаёт артефакт с неверным
  `sha256` (фикстура). → Нажать `Install`. → Сообщение об ошибке на странице (текст —
  из `installFromRegistry`, про несовпадение sha256), кнопка снова доступна, в
  `extensions/` ничего не появилось.

### Сеть, обновление каталога, источники

- **US-18. Нет сети при открытии.** Реестр недоступен. → Открыть вьюлет. → Секция
  каталога показывает ошибку с причиной (не «fetch failed», а текст с `cause`) и
  действие `Retry`; секция `INSTALLED` при этом полностью работоспособна.
- **US-19. Refresh каталога.** Вьюлет открыт, в реестр добавили запись. → Нажать
  `Refresh` в заголовке view (он же команда `extensions.refresh`). → Список
  перечитывается по сети, новая запись появилась. Без Refresh индекс за сессию
  тянется один раз.
- **US-20. Свой реестр.** Diode запущен с `--registry <путь-к-каталогу>` или
  `--registry http://127.0.0.1:8080/`. → Открыть вьюлет. → Показан этот реестр (та же
  view, тот же флоу установки), публичный не опрашивается.
- **US-21. Битая запись в реестре не роняет магазин.** Индекс содержит одну невалидную
  запись. → Открыть вьюлет. → Остальные записи показаны, битая пропущена, диагностика —
  в лог (философия `scanExtensions`: битая запись — пропуск, битый файл — ошибка).

## Эскиз устройства

Не проектная спека, а рамка — детали фиксируются при реализации.

- **Сервис** — `contrib/extensions/`: контракт и DI-токен в `common/`
  (`IExtensionsWorkbenchService`), реализация в `node/` (там `fetch`/`fs`), биндинг —
  в DI-модуле. Так вьюлет из `browser/` не импортирует `node/` и не требует
  исключения в `scripts/check-layers.mjs` (список таких исключений уже есть — не растим).
  Поверхность: `getCatalog()` (кэш в памяти + `refresh()`), `getInstalled()`,
  `install(id)`, `uninstall(id)`, `getMeta(id)`, `onDidChange` (событие для view).
  Источник — `createRegistrySource(cli.registry)`, `extensionsDir` — из
  `resolveUserDataPaths`, `host` — версии сборки (как в CLI-ветке `main.ts`).
- **Вьюлет** — `contrib/extensions/browser/extensionsComponent.ts`, `Component` по
  образцу `SearchComponent`: `InputElement` сверху, `ListViewElement` снизу, регистрация
  контейнера `EXTENSIONS_VIEWLET_ID` + view через `ViewsService`, команда показа
  `workbench.view.extensions` в `Actions/`.
- **Страница** — `contrib/extensions/browser/extensionEditorPane.ts`, реализует
  `IEditorPane` (`uri = extension:<id>`, `label = displayName`, `isModified = false`,
  `readOnly = true`, `viewState` нет), открывается через `EditorService.openPane`.
- **Сообщения** («reload window to activate», ошибки) — временная запись статус-бара
  (общий `showTransientNotice`, тостов в проекте нет) плюс статус на самой странице.
- **Прогресс установки** — неопределённый: `fetchArtifact` не отдаёт прогресс скачивания
  (в `IExtensionRegistrySource` такого канала нет). Проценты — только вместе с
  расширением контракта источника, в этом шаге не делаем.

## Чего сознательно не делаем

- **Горячую активацию установленного.** Требует dispose-цепочки вкладов и ре-скана
  (Extensions.md, Phase 7); вместо неё окно перезагружается целиком — процесс поднимается
  заново с теми же аргументами. Когда горячий reload появится, из US-11/US-14/US-15 уйдёт
  кнопка `Reload Window`, остальное не изменится.
- **Дисковый кэш индекса и оффлайн-режим.** Отложено сознательно (решение 4).
- **Категории, сортировки, рейтинги, «популярное», авто-обновление** — в реестре трёх
  записей это UI ради UI; `categories` вдобавок пока нет в мете (см. открытые вопросы
  в [Marketplace.md](Marketplace.md)).
- **Установку из списка одной кнопкой** (inline-кнопка строки в VS Code) — установка
  живёт на странице, чтобы решение принималось после просмотра readme и совместимости.
- **Встроенные расширения в списке.** `INSTALLED` показывает user-каталог: builtin
  нельзя удалить, и в списке они были бы мёртвыми строками.
- **Установку конкретной версии из UI.** `installFromRegistry` это умеет
  (`options.version`), пикер версий — позже.

## Открытые вопросы

- Перезагрузка окна оставляет висеть процесс-супервизор (заблокирован в `spawnSync`,
  держит терминал и свою память). Плата за то, что новое окно не дерётся за терминал с
  шеллом; альтернатива — отдельный launcher на каждом старте, то есть лишние сотни
  миллисекунд к запуску всегда.
- Строка курсора на странице расширения подсвечена (тело — `ListViewElement`, а он всегда рисует
  курсор). Для прокручиваемого текста это лишнее; отключаемого курсора у виджета нет — если
  решим убирать, это задача в репозиторий tuidom, а не обход у нас.

- Метка вкладки при коллизиях: две страницы с одинаковым `displayName` от разных
  publisher'ов дадут одинаковые метки (у файлов эту разводку делает таб-стрип по пути;
