# Find All References — панель ссылок в сайдбаре

Статус: `[x]` сделано (v1).

Закрывает следующий стаб из [LSP.md](LSP.md) после definition и hover:
`languages.registerReferenceProvider` был no-op, показывать ссылки было негде.
Калька с VS Code: **Find All References** наполняет вьюлет сайдбара `REFERENCES`
списком «файл → строки со ссылками», Enter открывает файл на позиции ссылки,
F4/Shift+F4 обходят ссылки, не уводя фокус из редактора.

## Как устроено

Проводка — калька definition: seam `iReferenceSource` → RPC
`languages.provideReferences` (таймаут 5000 мс) → `EditorService.referenceSource`.
Ответ `textDocument/references` — это `Location[]`, форма совпадает с
definition-целью до байта, поэтому новых value-классов в стабе не потребовалось:
конвертер стокового `vscode-languageclient` строит тот же `new code.Location(...)`.
Расширение `diode-lsp-typescript` не менялось — `ReferencesFeature` клиента
регистрирует провайдер сам под capability сервера.

Несколько провайдеров на документ конкатенируются в порядке регистрации, сбойный
пропускается и не роняет остальных (проверено на трёх уровнях: стаб RPC, реальный
субпроцесс с фикстурой из двух провайдеров, живой `typescript-language-server`).

**Текста строк LSP не отдаёт** — только `uri` + `range`. Это единственная часть
без прецедента: `referencePreview.ts` добирает строку сначала из открытой модели
(в ней видны несохранённые правки, которые сервер тоже видит через didChange),
иначе читает файл через `IFileSystemProviderRegistry`. Каждый файл читается один
раз на запрос; хвост строки каппится у истока (урок тормозов окна поиска —
случай 1 в `docs/TODO/SearchPerformance.md` в git: ссылка в минифицированном
файле иначе тащит в строку списка сотни килобайт).

UI — contrib `references`: `ReferencesComponent` (вьюлет и список),
`ReferencesService` (запрос → превью → панель, guard `requestSeq` от устаревших
ответов). Строки списка **общие с панелью поиска** (`searchResultRows`): «файл со
счётчиком + строки с подсветкой вхождения» — одна визуальная идиома, расходиться
ей незачем. Вынос общего контрола из `SearchComponent` сознательно НЕ делался:
по конвенции из `searchResultTree.ts` общий хелпер выносим на третьем
потребителе, а рефакторинг внутри фичи мешал бы её ревью.

## Команды

| Команда | Бинд | Что делает |
|---|---|---|
| `references-view.findReferences` | Ctrl+K Ctrl+R, Shift+Alt+F12 | Найти ссылки на символ под кареткой |
| `workbench.view.references` | Ctrl+K R | Показать вьюлет (пункт меню View) |
| `references-view.next` / `.prev` | F4 / Shift+F4 | Следующая/предыдущая ссылка |
| `references-view.clear` | — | Очистить панель («⋯»-меню) |
| `references-view.collapseAll` / `.expandAll` | — | Свернуть/развернуть («⋯»-меню) |

Аккорд Ctrl+K Ctrl+R объявлен основным биндом, а не канонический VS Code-овский
Shift+Alt+F12: F-клавиша с модификаторами доезжает не на всяком терминале, и без
запасного пути фича осталась бы доступной только из палитры (та же причина, что
у Search и Extensions). Канонический бинд при этом объявлен вторым и работает
там, где терминал его кодирует.

Команда показа вьюлета — наше отступление от VS Code, вынужденное отсутствием
activity bar: без неё к панели не вернуться, переключившись на Explorer.

## Люфты v1

- Нет истории прошлых запросов и удаления отдельного результата из списка
  (в VS Code есть и то, и другое).
- Нет иерархии каталогов и переключателя list/tree — плоско по файлам, как в
  VS Code-овской References view.
- Нет peek-виджета (`Shift+F12`): это редактор внутри оверлея со своим скроллом и
  роутингом клавиш; в терминале панель полезнее. Решение осознанное, не «не успели».
- Отмены RPC нет — таймаут плюс счётчик запросов против устаревших ответов
  (общий люфт с completion и hover).
- Каретка не на слове — команда молчит, а не показывает пустую панель.
- Без открытой папки (запуск с одним файлом) панели нет: вьюлеты сайдбара
  собираются на workspaceFolder. Общее свойство всех вьюлетов — Explorer,
  Search и Extensions ведут себя так же.
