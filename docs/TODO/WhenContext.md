## Осталось

### [ ] Парсинг и вычисление when-выражений
Сейчас используется `new Function(...)` с подстановкой переменных. Заменить на полноценный парсер when-выражений (`&&`, `||`, `!`, сравнения) для безопасности и расширяемости.

Что уже пришлось подпереть внутри этого подхода (и что парсер должен снять):
- **Точечные ключи расширений** (`supermaven.isProUser`, их приносит команда `setContext`)
  раскладываются вложенными объектами под корневым сегментом, а сам скоуп подаётся
  через `with` — параметром `new Function` имя ключа быть не обязано. Остаточное
  ограничение: ключ, чей корень столкнулся с плоским ключом, вычислителю не виден
  (в примитив вложить нечего), и имена, которые в выражении не написать словом
  (`foo-bar`, `2fa`, `class`), остаются недостижимыми. Настоящий парсер про
  синтаксис JS не знает и берёт имя ключа целиком, каким бы оно ни было.
- **Имена из глобального объекта** (`constructor`, `toString`) выражение видит:
  `with` не находит их в скоупе и уходит в глобальный скоуп функции, где они есть.
  Выражение по такому ключу истинно вместо честной лжи. Парсер это снимает сам —
  ему неоткуда взять глобальный скоуп.
- **Оператор `in`** (VS Code умеет `key in arrayKey`) не поддержан: значения у нас
  примитивные, массив из `setContext` сводится к своей истинности.
