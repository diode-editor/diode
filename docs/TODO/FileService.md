## PR 5 — асинхронная загрузка модели

Проверено в 4.2 OpenPerformance (документ на диске): асинхронная загрузка там не понадобилась — модель
рождается синхронно с первым куском (4 МиБ) и первым экраном, остальное дочитывает фон внутри буфера, а
байты идут через свой seam `IRandomAccessFile` (`pread`), не через `IFileService`. PR 5 остаётся за 4.5
(стриминговая загрузка в PieceTree), где чтение всего файла и становится асинхронным.

- [ ] `TextFileModel.resolve()`, `registry.resolve(uri): Promise<ref>` с дедупом по незавершённой
  загрузке (второй `resolve` того же uri ждёт тот же промис), ветка `file:` в `EditorService.openUri`
  сливается с `openVirtualUri`, слежение через `onDidFilesChange`. Снимает последние записи
  `node:fs` в `NODE_IMPORT_DEBT`: `textFileModel.ts`, рестор вкладок (`editorPaneFactory.ts`) и
  историю навигации. Делать **вместе со стримингом** этапа 4: иначе загрузку переписываем дважды, а
  `FileReadStream` в capabilities сервиса — уже зарезервированный слот под него.

Что меняется (синхронная цепочка сейчас: `openFile` → `openUri` → `modelRegistry.acquire` →
`createFileModel` → `model.openFile` → `readFileSync`):

- `openFile(path)` остаётся `void`, но вкладка появляется не в том же тике; вызовы «открыл → сразу
  работаю с активным редактором» без `await` — в `referencesComponent.ts` и `searchComponent.ts`;
- рестор вкладок становится `async` с сохранением порядка (последовательный `await` или вставка по
  индексу), флаг `restoring` переживает `await`; файлы из CLI — последовательно, первый кадр не ждёт
  остальных; активная вкладка читается первой, прочие — после кадра (единственное место, где
  сервис **ускоряет** старт);
- `revertToDisk()`/`reopenWithEncoding()` → `Promise<boolean>`; автоперечитка по watcher'у
  проверяет версию буфера после чтения (эталон); file-сторона диффа (`acquireFileModel`);
- **тесты:** ~570 вызовов `openFile`/`openUri` без `await` в ~100 файлах — codemod или постепенный
  перевод на `InMemoryFileSystemProvider` (заодно разгружает прогоны, см. [TestFlakes](TestFlakes.md)).

Новые классы гонок: двойное открытие одного файла (дедуп в реестре); открыли A, пока грузится —
открыли B (побеждает последний запрошенный, счётчик запросов на группу); вкладку закрыли, пока шла
загрузка (результат выбросить, ссылку освободить); save во время перечитки и наоборот (очередь, как
`saveSequentializer` эталона). Не копировать буфер на границе сервиса, `fstat` на открытом
дескрипторе вместо отдельного `stat`, `fs.promises.readFile` на больших файлах — только с замером на
`xlarge`.
