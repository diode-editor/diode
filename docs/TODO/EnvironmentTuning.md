# [~] EnvironmentTuning — подсказки пользователю по тюнингу окружения

Трекер требований/рекомендаций к окружению (терминал, мультиплексор, SSH), от которых
зависит корректная работа редактора. Цель — научиться **детектировать** такие
ситуации и **подсказывать** пользователю, что подкрутить, а не «молча чинить» за него
(тем более не ценой регрессий вроде утечки кодировки в соседние панели tmux).

Статусы: `[ ]` — открыта, `[~]` — в работе, `[x]` — сделана.

---

## Мотивация

Часть функций редактора работает корректно только при определённых настройках
окружения, которые пользователь не обязан знать. Пример — Ctrl+Tab в tmux (см. ниже):
модификатор физически теряется на стыке kitty→tmux ещё до приложения, и никакой
конфиг diode это не чинит. Мы намеренно не подкручиваем чужой tmux из кода, поэтому
нужен механизм, который честно объяснит пользователю причину и даст рецепт.

---

## Открытый вопрос: как доносить до пользователя

Способ подачи ещё **не выбран**. Кандидаты (идеи, без обязательств):

- намёк/индикатор в статусбаре, когда обнаружено «недонастроенное» окружение;
- one-shot нотификация при старте (с возможностью «больше не показывать»);
- команда-«doctor» — отчёт по окружению со списком рекомендаций;
- запись рекомендаций в лог.

Источник сигналов у нас уже есть: `TerminalEnvironmentService`
(`src/vs/workbench/services/terminalEnvironment/node/terminalEnvironmentService.ts`) детектит
окружение и capability `extended-keys` (env-хинты + fire-and-forget проба
клавиатурного протокола). Его естественно переиспользовать как вход для подсказок.

## Список рекомендаций

Формат пункта: симптом → причина → что подкрутить.

### [ ] Linux: исчерпан лимит inotify (ENOSPC/EMFILE) — сказать это пользователю, как VS Code

- **Симптом.** На старте (или при раскрытии дерева) файловые watcher'ы отваливаются:
  ОС отказывает в новом watch'е с `ENOSPC: System limit for number of file watchers reached`
  (реже `EMFILE`). Раньше это **роняло весь редактор**: chokidar делал `emit('error')`,
  слушателя не было, EventEmitter бросал исключение из async-потрохов → процесс умирал.

- **Что уже сделано.** Watcher'ы больше не роняют процесс и пишут warn с подсказкой:
  - `ChokidarFileWatcher` и `ChokidarTreeWatcher` (`src/vs/platform/files/node/`) — канал `files.watcher`
    (обход дерева с недавних пор живёт в отдельном процессе, и его записи доезжают в тот же
    канал через протокол `treeWatcherProtocol.ts` — сообщение `log`);
  - `FileTreeDataProvider` → `ExplorerService` (`onWatchError`) — канал `filetree.watcher`;
  - общий разбор ошибки и текст подсказки — `describeFileWatchError` (`src/vs/platform/files/common/fileWatchErrors.ts`).
  Редактор при этом работает, теряется только live-reload (settings.json/keybindings.json,
  внешние изменения открытых файлов, авто-обновление ветки дерева).
  Заодно ужаты дефолты `files.watcherExclude`
  (`src/vs/workbench/common/configuration/filesConfiguration.ts`): рекурсивный watcher больше
  не заходит в `node_modules`, `.git`, каталоги сборки и кеши, и на типовом дереве в лимит
  не упирается вовсе (замер на репозитории diode: 94 176 watch'ей → 2 447). Это снижает
  вероятность ENOSPC, но не убирает его — на большом дереве или низком лимите он остаётся,
  и пункт ниже по-прежнему открыт.

- **Что осталось (главное).** Пользователь ничего не видит — только строчка в логе. VS Code
  в этой ситуации показывает **уведомление** вида «Unable to watch for file changes… ENOSPC»
  со ссылкой на инструкцию, как поднять лимит. Нам нужно то же самое, как только появится
  механизм уведомлений (см. раздел «как доносить до пользователя» выше):
  - одно уведомление на сессию (не спамить на каждый упавший watcher — их десятки);
  - текст с рецептом: `sysctl fs.inotify.max_user_watches` → поднять и записать в
    `/etc/sysctl.d/*.conf` (`fs.inotify.max_user_watches=524288`);
  - деградацию сформулировать честно: «внешние изменения файлов не отслеживаются».

- **Заодно.** Это первый кандидат на общий паттерн «редактор жив, фича деградировала» —
  такие вещи должны становиться уведомлением, а не молчаливой строкой в логе.

- **Ставка выросла.** С появлением `SharedTreeWatcher` (`src/vs/platform/files/node/`)
  на одном обходе едет несколько подписчиков, поэтому упавший по ENOSPC обход теперь
  разом лишает слежения всех, кто на нём сидел, — а `ITreeFileWatcher` такого события
  наружу не отдаёт вовсе. Уведомление станет нужнее, и вместе с ним понадобится
  канал «обход умер» до подписчиков.

- **Нативный обход (`@parcel/watcher`, [FileTreePerformance](FileTreePerformance.md)) лимит тоже не
  поднимает**: на Linux под ним тот же inotify, и VS Code ловит там тот же ENOSPC.

- **Переезд обхода в свой процесс ничего здесь не изменил** (и не должен был):
  лимит inotify — общий для процессов пользователя, а не для одного. Что изменилось —
  цена отказа для пользователя: раньше растущее число подписок душило главный цикл
  редактора и ENOSPC приходил как «редактор отвис», теперь отклик не меняется вовсе,
  и молчание стало **единственным** признаком отказа. Замер на дереве с ~55k
  каталогов (по три прогона на сборку): отклик главного цикла до переезда —
  worst 779–901 мс и 12–13 просадок >100 мс за первые 10 с, после — worst
  46–177 мс и 0–1 просадка; обход в обоих случаях умирает по ENOSPC примерно на
  9-й секунде.

### [~] tmux + kitty: Ctrl+Tab / Ctrl+Shift+<key> не доходят (приходит голый Tab/легаси)

Разобрано: модификатор теряется на стыке kitty→tmux (kitty не понимает `modifyOtherKeys`, которым
tmux просит расширенные клавиши); лечится только tmux ≥ 3.5 с `extended-keys always` +
`extended-keys-format csi-u`. Устройство, бисекция по слоям и почему не чиним кодом —
[arch/workbench/Keyboard.md](../arch/workbench/Keyboard.md#где-теряется-клавиша-tmux-kitty-iterm2);
рецепт для пользователя и фолбэк `Ctrl+PageDown`/`Ctrl+PageUp` — [public/TMUX.md](../public/TMUX.md).

- [ ] **Детектить и подсказывать.** Ситуация «внутри tmux, но расширенные клавиши фактически не
  приходят» (`mode_tmux` активен, а `noteExtendedKeysObserved` так и не сработал спустя N вводов) →
  подсказка: «жми Ctrl+PageDown, либо tmux ≥ 3.5 для Ctrl+Tab». Способ подачи — из раздела «как
  доносить» выше.

### [ ] Мак: Cmd, Option и tmux — что подсказывать маководу

Мак-раскладка и Keyboard Doctor — [arch/workbench/Keyboard.md](../arch/workbench/Keyboard.md),
таблица эмуляторов и рецептов — [MacKeybindings](MacKeybindings.md#эмуляторы--не-проверено-на-живом-маке).
Доктор уже отдаёт рецепт под опознанный эмулятор, но только в отчёте. Довести до «детектим и
подсказываем»:

- [ ] Рецепт эмулятора — подсказкой, когда окружение опознано как мак, а рунг ниже возможного для
  эмулятора (например, iTerm2 без tmux, а super так и не пришёл).
- [ ] Под tmux ОС осталась «default», а клиент — маковский терминал: подсказать
  `set -ag update-environment LC_DIODE_PLATFORM`.
- [ ] Под tmux: Cmd-раскладка только без tmux, внутри — Ctrl-подслой; для Ctrl+Shift/Ctrl+Tab —
  tmux ≥ 3.5 (пункт выше).
