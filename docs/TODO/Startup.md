# [~] Startup — параметры запуска и стартовое состояние окна

Что делает `diode`, когда его зовут: разбор аргументов командной строки и то,
каким окно поднимается. Соседние документы: [Logging](Logging.md) (уровни логов
с CLI), [Marketplace](Marketplace.md) (флаги управления расширениями).

Статусы: `[ ]` — открыта, `[~]` — в работе, `[x]` — сделана.

---

## Решение: запуск без аргументов

`diode` без позиционных аргументов поднимает **пустое окно**. Конкретно:

- воркспейс не открывается — ни Explorer-корня, ни индекса файлов, ни
  вотчеров, и расширения видят `workspace.workspaceFolders === undefined`;
- **текущий каталог не трогается вообще** — ни как папка, ни сканированием.
  Это явное требование: `cd ~ && diode` не должен уходить обходить домашний
  каталог;
- вкладки прошлой сессии не восстанавливаются: сессия живёт у воркспейса,
  а его нет;
- сайдбар при этом собран, Explorer показывает подсказку «No folder opened.»,
  магазин расширений работает как обычно. Выход из пустого окна —
  `workbench.action.files.openFolder` (Ctrl+K Ctrl+O).

**Почему не как в vscode и не как в vim.** Обсуждались три поведения:

| подход | кто так делает | почему не взяли |
| --- | --- | --- |
| восстановить последний воркспейс | vscode (`window.restoreWindows`), zed, jetbrains | в GUI-IDE это замена бессмысленной cwd; в терминале даёт «стою в одном проекте, открылся другой» |
| открыть cwd как папку (`code .`) | terminal-native | cwd бывает `~` или `/`, и тогда запуск уходит в обход гигантского дерева |
| пустой scratch-буфер | vim, helix, emacs, micro, nano, kakoune | у них нет понятия workspace folder, а у нас есть — буфер не решает, что делать с Explorer/Search/SCM |

Взяли честное пустое окно: оно ничего не угадывает, а всё, что человеку нужно
в этом состоянии (недавние папки, действия, справка), принесёт **welcome page**
— отдельная задача.

## Сделано

- [x] Запуск без позиционных аргументов вместо `exit 1` «Usage».
- [x] Регистрация вьюлетов сайдбара расцеплена с `setWorkspaceFolder`:
      `WorkbenchComponent.registerViewContainers()` зовётся из `mount()`, а
      `setWorkspaceFolder` отвечает только за корень/стор/индекс.
- [x] Смена корня на живом приложении наполняет дерево (`Open Folder` из
      пустого окна): `setRootPath` только пересоздаёт провайдер, а
      `TreeViewElement` грузится исключительно через `refresh()` — раньше
      Open Folder оставлял пустую панель.
- [x] `workspaceFolders` расширениям без папки — пустой список вместо
      `process.cwd()` (наружу уходит `undefined`, контракт VS Code).
- [x] `-g` / `--goto` — позиционные читаются как `file[:line[:column]]`.
- [x] `-d` / `--diff <a> <b>` — дифф-вкладка прямо со старта.
- [x] `--disable-extensions` — гасит пользовательские расширения, встроенные
      остаются (дословно `_isDisabledInEnv` эталона).
- [x] `--extensions-dir <dir>` — каталог расширений отдельно от `--user-data-dir`.
- [x] `--log <level>` / `--log <channel>:<level>` (повторяемый) и `--verbose`.

## Открыто

- [ ] **Welcome page** — содержимое пустого окна: недавние папки, Open Folder,
      New File, ссылки. Отдельная задача; вместе с ней имеет смысл завести
      `workbench.startupEditor` (`none` | `welcomePage` | `newUntitledFile`),
      чтобы поведение выбирал человек, как в эталоне.
- [ ] **Список недавних папок** — нужен и welcome page, и команде Open Folder
      (сейчас она просит ввести путь руками, без автодополнения и истории).
- [ ] Флаги эталона, которые сознательно не брали:
      - `-a` / `--add` — multi-root у нас нет;
      - `-w` / `--wait`, `-n` / `--new-window`, `-r` / `--reuse-window`,
        `--status` — у однопроцессного TUI смысла не имеют;
      - `--merge` — трёхстороннего слияния нет;
      - `--disable-extension <id>` (точечный) — тот же код, что у общего флага,
        просто не понадобился.
- [ ] `--log-file <path>` / `--no-log-file` — хвост из [Logging](Logging.md).
- [ ] `DEFAULT_LEVEL` логов снизить с `Trace` до `Info` (сейчас `--log` умеет
      только опускать планку от «всё»).
- [ ] Несуществующий путь в аргументах: `diode new-file.ts` открывает пустую
      вкладку, но поведение не описано и не покрыто.
