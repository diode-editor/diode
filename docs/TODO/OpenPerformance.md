## Откуда идём

Первый отчёт — PR #318 (CI, 4 ядра, 2026-09-27): `small` до текста 446 мс при поле бинаря 146 мс
(~300 мс «кухни» на файле любого размера), `xlarge` (13 МБ) — 3.1 с (жадные проходы по всем строкам),
`log500m` (497 МБ) — 88 с и OOM на первой правке (полная загрузка в одну JS-строку; у V8 потолок
строки ≈ 512 МБ символов).

## План

Порядок важен: сначала честная линейка, потом самое дешёвое с самым большим эффектом, пьес-три и
стриминг — когда жадные проходы сняты, иначе их выигрыш не будет виден.

### Этап 0 — линейка `[x]`

Бенч считает «наших мс» от пола `node -e ""` (не `node --version`: тот отвечает до подъёма V8) и
печатает лестницу вех из процесса (`DIODE_STARTUP_TRACE`); рабочая нагрузка после открытия (Go to

### Этап 2 — жадные проходы: файл до десятков МБ открывается как маленький `[x]`

Цель: `xlarge` (13 МБ / 200 К строк) до текста ≤ `small` + 100 мс, клавиша (вставка, Enter, undo,
save) ≤ 16 мс и не зависит от размера файла. Каждый PR меряется `bench:open --sizes=small,xlarge`
до и после, цифры — в описании PR.

Итог (CI 2026-10-23, bench-data `3cc5d68f` и гейт #793): `xlarge` до текста 263 мс при `small` 160
(наших 238 против 135 — **+100 мс**, это чтение и декод 13 МБ; было 1306 против 125 на старте этапа);
в установившемся режиме Enter 8, undo 5, insert 5 мс — **не зависят от размера** (`small` 10–11);
первая клавиша сразу после Go to Line (публичный бенч) — insert 46, Enter 25, save 102 мс: бэклог
фоновой токенизации (~20 с главного потока на CI) и sync — к этапу 3. Peak RSS `xlarge` 472 МБ
(было 673). Гейт CI держит обе цифры (пункт 6). 5a (IPC на структурном клоне, #794): пауза
главного потока на подъёме extension host ~85 → ~30 мс. Открыто: QuickDiff.

Исходная точка (CI 2026-10-22, `bench-data` `436e1bb`): документ собран к 196 мс, кадр с текстом —
1306 мс; клавиши — вставка 240, Enter 386, undo 308–315, save 387 мс; `Ctrl+End` уже 8 мс.

Профиль (живой редактор из исходников, 2026-10-22; абсолютные числа раздуты tsx, доли — нет):

| что | открытие | клавиши (10+10+10) | почему |
|---|--:|--:|---|
| раскраска вхождений `paintRangeBackground` | ~750 мс | ~12 с из ~15 с рендера | курсор на `const`/`export` — 200 К совпадений, каждое обходит все видимые строки: O(совпадений × строк экрана) |
| `computeWordOccurrences` | — | 1.8 с | синхронно в рендере, на каждой правке, по всему файлу |
| `LineWidthCache.getMaxWidth` | ~1.8 с | 1.5 с | первый кадр меряет все строки `measureTextWidth`; после правки — максимум по всем |
| `buildProjection` | ~220 мс | 4.3 с | пересобирается целиком на каждой правке (`ensureCursorVisible`, рендер) |
| `recomputeFoldingRegions` | ~95 мс | 0.6 с | indentation-фолдинг синхронно на каждой правке |
| `pushInitialState` | 140 мс | — | после кадра, но держит поток |

Эталон: вхождения — асинхронно с задержкой `occurrencesHighlightDelay`, рисуются декорациями,
которые спрашиваются по диапазону вьюпорта; ширина контента растёт по мере отрисованных строк;
проекция строк правится по месту (префиксные суммы); indentation-фолдинг — асинхронно с капом
5000 регионов (`MAX_FOLDING_REGIONS_FOR_INDENT_DEFAULT`); sync с extension host — до 50 МБ
(`_MODEL_SYNC_LIMIT`).

### Этап 4 — гигантские файлы: отдельный режим «только чтение» со стримингом `[~]`

Решение человека 2026-10-22: до поста; гигантский файл — **отдельный режим**: открывается только
для чтения сразу и стримингом, редактирование — по кнопке в тосте; follow (`tail -f`) для логов — в
первой версии. Прецедент эталона — уведомление большого файла «tokenization, wrapping, folding … turned
off» с кнопкой «Forcefully Enable Features»; режим «на диске без лимита размера» — отступление: эталон
читает файл в память целиком. Read-only редактор уже есть ([ReadonlyEditor.md](ReadonlyEditor.md)).

Решения человека 2026-10-23: порог — как эталон, **20 МБ / 300 К строк** (настройка); follow — **сам**,
когда курсор на последней строке (как `less +F` и Output-панель), плюс команда и индикатор в
статус-баре; этап идёт по очереди с 4.1, 4.3 и 4.4 — параллельно.

PR по порядку:
