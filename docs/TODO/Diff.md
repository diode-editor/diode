# Diff — дифф-вкладка и команды сравнения

Статус: `[~]` — дифф v2 на двух настоящих редакторах, side-by-side с авто-inline, всё семейство
команд сравнения и живой пересчёт сделаны; история — в git. Устройство и принятые решения —
[arch/workbench/EditorPart.md](../arch/workbench/EditorPart.md#дифф-вкладка). Открыто — ниже.

## Интерактив (фаза 2)

- [ ] **Раскрытие свёрнутого куска жестом.** Каретка или указатель на плашке «⋯ N unchanged
  lines» → Enter или клик раскрывает кусок согласованно на обеих сторонах, выравнивание
  сохраняется, скролл не прыгает. Большой кусок — порциями (upstream `revealLineCount: 20`),
  целиком — отдельной командой «Expand All».
- [ ] **«Diff: Switch Side»** (и клик в другой колонке): активной становится другая сторона,
  каретка встаёт на **соответствующую** строку, а не в начало файла.
- [ ] **F7 / Shift+F7 — «Go to Next/Previous Difference».** Каретка прыгает к следующему
  изменению; внутри свёрнутого куска — кусок раскрывается; строка попадает в видимую область.
  F7 при `editorTextFocus` уже занят `editor.action.wordHighlight.next/prev`: в диффе бинд нужен
  с `when` на `isInDiffEditor` и весом не ниже `EditorContrib` — как
  `editor.action.accessibleDiffViewer.next` у эталона.
- [ ] **Кликабельные стрелки revert на ханках** (как в VS Code) — нужен hit-test колонки
  гуттер-маркеров в `EditorElement`; сейчас revert — только командой «Diff: Revert Hunk» по каретке.
- [ ] **Original-номера строк у зон-призраков в inline** — VS Code показывает их отдельной
  колонкой; у нас гуттер зоны пуст. Добавить, если попросится.

## Краевые случаи (фаза 6)

- [ ] **Большой файл и таймаут.** Десятки тысяч строк → результат появляется; при упоре в
  `MAX_DIFF_COMPUTATION_MS` — грубый дифф, приложение не замирает, и пользователь видит, что
  результат приблизительный.
- [ ] **Бинарный или нечитаемый файл** → сообщение вместо мусора на экране; вкладка закрывается
  нормально.
- [ ] **Пробелы.** EOL сам по себе изменений не даёт (уже так); для пробелов — тумблер «Toggle
  Ignore Trim Whitespace» с наблюдаемым эффектом.
- [ ] **Дифф файла из коммита (GRAPH):** активация коммита → список файлов → вкладка
  `<файл> ↔ <shortSha>~` (`commit^ ↔ commit`). Нужен парсер тел ханков или чтение обеих сторон
  через `git:`-провайдер (`extensions/git/lib/diff.ts` парсил только заголовки и удалён); см.
  follow-up'ы GRAPH в [SourceControl.md](SourceControl.md#graph).

## Долг

- [ ] **Два `IRange`.** В `editor/common/core/` сосуществуют наш `iRange.ts`
  (`{ start: IPosition; end: IPosition }`) и upstream-овский из `range.ts` (1-based,
  `endExclusive`). Выбран адаптер в одной точке (`contrib/scm/browser/quickDiffDecorations.ts`,
  правило — [arch/Editor.md](../arch/Editor.md#координаты-ядро-0-based-вендор-1-based));
  миграцию ядра на upstream-примитивы не начинали — несоразмерно ради одного места вызова.
- [ ] **Приватные команды вместо неймспейса `scm`.** `scm.createSourceControl`,
  `QuickDiffProvider` и `registerTextDocumentContentProvider` в `vscode.d.ts` закомментированы;
  транспорт — приватные `diode.git.*`/`diode.scm.*`-команды. Канонический путь нужен, когда
  появится второй источник SCM-данных или сторонние SCM-расширения.
- [ ] `DiffViewModel.rows` остался без потребителя (покрыт своими юнитами) — чистка отдельно.

## Осознанные люфты и non-goals

- Режим `auto` (side-by-side/inline по ширине) после первого тумблера возвращается только сбросом
  стейта `DIFF_VIEW_MODE_STATE`.
- Find идёт по активной стороне (в VS Code — два независимых виджета); матчи, как везде у нашего
  find, статичны до следующего пересчёта.
- Снимочная сторона «(on disk)» (Compare with Saved) сама не освежается — `file:` событий не даёт;
  освежает повторный вызов команды.
- Сплит дифф-вкладки дублем не делится — новая группа открывается пустой (люфты групп —
  [arch/workbench/EditorPart.md](../arch/workbench/EditorPart.md)).
- Не делаем: staging по диапазонам (`git.stageSelectedRanges`), три колонки для merge-конфликтов,
  word wrap внутри диффа (стороны выравниваются зонами по view-строкам, перенос развёл бы
  половины — [WordWrap.md](WordWrap.md)).
