# Синхронизация документов с extension host'ом: один дельтовый канал (G3)

Статус: `[~]` в работе.

Текст документа попадает в субпроцесс расширений по двенадцати путям, и ни
один не передаёт дельту: push `editor.didOpen`/`didChange` везёт полный текст
на каждую правку (с коалесингом в микротаск), а девять `languages.provide*` и
will-save ещё раз везут `text` целиком без версии. Субпроцесс сводит всё в
`DocumentSyncTracker.sync()`, который любое расхождение превращает в одну
full-range правку: LSP-сервер с incremental sync получает весь документ на
каждое нажатие, версия документа берётся то из ядра, то из локального `+1`, а
корректность держится на инварианте «всё пишется через трекер» (уже дважды
ломался: запрос обгонял коалесированный didChange).

Как в vscode: один канал `$acceptModelChanged(uri, {changes, versionId, eol})`
синхронно на каждое изменение модели, запросы провайдеров несут только
ресурс — порядок сообщений в одном канале заменяет версию в запросе.

## План

1. [~] Батч-событие модели `ITextDocument.onDidChangeModelContent`
   (`{changes: {range, text}[], versionId, eol, isFlush}`) — аддитивно, рядом
   с построчным `onDidChangeContent`.
2. [ ] Зеркало в субпроцессе (`ExtHostTextDocument` — строки и
   `acceptChanges`) и дельтовый `editor.didChange`: адаптер на новом событии,
   без микротаска и без гейта подпиской (пропуск любого didChange портит
   зеркало); запросы пока везут текст, субпроцесс только сверяет его с зеркалом.
3. [ ] Запросы без текста: `text` → `versionId` в seam-интерфейсах,
   contrib-сервисах, проводе и обработчиках субпроцесса; реестр
   синхронизированных документов на хосте вместо копий гейта 8 МБ; лимит —
   один раз на didOpen (50 Mi символов, порог опцией хоста).

## Не делаем

Отложенную эмиссию событий модели (`beginDeferredEmit` эталона), префикс-суммы
для offset, перевод существующих подписчиков `onDidChangeContent` на новое
событие, debounce didChange, синхронизацию по жизненному циклу моделей вместо
вкладок (это E3), `reason` Undo/Redo (необязательный PR4 исследования).
