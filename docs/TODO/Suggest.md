# Suggest — автодополнение и панель описания

Статус: **[~] итерация «suggest × LSP» сделана** — подсказки стокового
`typescript-language-server` доезжают до попапа, список сортируется и фильтруется по
серверным данным, панель описания включается тумблером, авто-импорт применяется вместе со
вставкой. Открыто — «Дальше» в конце файла.

Контекст стека и грабли LSP-стороны — [LSP.md](LSP.md), раздел «Автодополнение».

## User stories (приёмочный чек-лист)

Каждая закрыта тестом; после релиза по ним проводится ручная проверка.

### Подсказки от language server

- **US-0. Пункты вообще доезжают.** Открыть `.ts`, набрать `d.` → в попапе члены `Date`.
  Регресс, ради которого написан `extensionHost.typescriptLsp.completion.test.ts`: без
  экспорта `CompletionList`/`SnippetString` из стаба конвертер клиента падал на каждом
  ответе, и попап молча оставался пустым (проверено — прогон без экспорта висит 60 с).
- **US-1. Члены типа.** `d.` + Ctrl+Space → `getTime`, `toISOString` с иконками kind.
- **US-2. Триггер-символы.** Набор `.` открывает попап сам, с `triggerKind =
  TriggerCharacter`; список фильтруется от границы, заданной сервером, и не схлопывается.
- **US-3. Порядок и фильтрация серверные.** Сортировка по `sortText`, матчинг по
  `filterText`; совпадения с начала — выше; пункты без `sortText` держат порядок
  провайдера. Слова из буфера подмешиваются только там, где провайдер не задал `range`.
- **US-4. Неполный список.** Ответ с `isIncomplete` при доборе символа перезапрашивает
  источник, а не сужается локально.
- **US-5. Ответы не наезжают.** Медленный ответ, пришедший после нового запроса или после
  закрытия попапа, игнорируется (`LatestRequest`).

### Панель описания

- **US-6. Описание выбранного пункта.** Панель показывает сигнатуру и документацию.
- **US-7. Ленивая догрузка.** Описание тянется через `resolveCompletionItem` только для
  выбранного пункта, с кэшем и дедупом; пока панель скрыта — не запрашивается вовсе.
- **US-8. Тумблер.** Ctrl+Space при открытом попапе разворачивает/сворачивает панель;
  по умолчанию свёрнута, выбор переживает рестарт (`editor.suggest.showDetails`, global).
- **US-9. Геометрия.** Панель справа от списка, при нехватке места справа — слева;
  не выше списка; длинный текст переносится по словам.
- **US-10. Тема.** Панель на существующих токенах `editorSuggestWidget.*`, новых цветов
  не заведено.

### Вставка

- **US-11. Замена по серверному range.** Accept заменяет ровно диапазон источника, с
  учётом добранных с триггера символов.
- **US-12. Авто-импорт.** Пункт из другого модуля дописывает `import` — правки-спутники
  приезжают на resolve и применяются вместе со вставкой **одной** undo-транзакцией.
  Молчащий сервер вставку не морозит (ожидание resolve — 300 мс).
- **US-13. Сниппет-синтаксис не течёт в буфер.** У пункта `insertTextFormat = Snippet`
  плейсхолдеры вырезаются. Полноценных табстопов нет — см. «Дальше».

### Устойчивость

- **US-14. Большой список.** Ширина содержимого считается один раз на смену списка и по
  выборке из 200 пунктов — тысяча пунктов не тормозит кадр.
- **US-15. Сервера нет.** Попап продолжает работать на словах из буфера.
- **US-17. Сервер медленный.** Срока ответа у запроса списка нет, как в upstream
  (`provideSuggestionItems`): language server на холодном старте или под нагрузкой
  думает секунды, и попап открывается его пунктами, когда ответ пришёл, — словами из
  буфера он не подменяется. Ненужный запрос гасится сам: новый запрос, триггер-символ,
  уход каретки из слова (другая строка, шаг влево, несловесный добор, выделение),
  уход фокуса, закрытие. Слово, добранное за время ожидания, сужает список сразу.
- **US-16. Демо.** Скриншот-сценарий `lsp-completion` (кадры `completion`,
  `completion-details`).

## Грабли, найденные на живом приложении

Обе не видны юнит-тестам: данные и раскладка корректны, а на экране — не то.

- **Панель есть в раскладке, но не на экране.** Описание приезжает асинхронно
  (`resolve`), уже после показа списка: на момент `openAt` виджет шириной в один
  список, и overlay-сессия запоминает эту геометрию. Дерево показывает
  `CompletionWidgetElement` 81×8 и панель 60×8 рядом со списком, а кадр — только
  список. Лечится пере-анкором сессии после смены содержимого
  (`SuggestComponent.refreshDetailsLayout`); `markDirty` на самом виджете не
  помогает. Тот же путь нужен и при сворачивании панели.
- **Слабый ассерт прячет неработающую фичу.** Первая версия скриншот-сценария
  ждала `/method|number/i` — а слово `number` есть в самом коде фикстуры, так что
  кадр снимался до появления панели, и сценарий был «зелёным» с пустой панелью.
  Ждать надо текст, которого в буфере быть не может (`(method)` из сигнатуры).
- **Срок ответа, превращённый в «пусто», — это подмена ответа.** У запроса списка был
  срок 1500 мс (скопирован с will-save в первом коммите автодополнения, ещё до токенов
  отмены). Истёк — хост отдавал «пусто», ядро открывало попап словами из буфера, и
  открытый попап уже не перезапрашивался: после `reply.` человек видел `from, defs,
  import…` вместо членов `int`, пока не закрывал попап. Проявлялось флаком
  `e2e/pythonLsp.test.ts` под двумя воркерами: basedpyright отвечал на точку за
  1,7–2,6 с. Узкий прогон под нагрузкой (четыре холостых цикла на четырёх ядрах) давал
  6 падений из 6 до правки и 0 из 6 после. Лечится не сроком побольше, а его
  отсутствием — как в эталоне.

## Дальше

- **Сниппет-сессия** — табстопы, Tab/Shift+Tab по плейсхолдерам, Esc из сессии. Сейчас
  плейсхолдеры вырезаются (US-13).
- **Markdown в описании** — рендерера markdown в tuidom нет; документация показывается
  как текст.
- **Скролл панели** — длинное описание обрезается по высоте списка.
- **Отмена resolve** — resolve пункта идёт без токена (ответ кэшируется и общий у панели описания и accept); ограничен только сроком ответа. Сам запрос списка отменяется сразу: токен билета `LatestRequest` доезжает до провайдера (H2).
- **`commitCharacters`** — клиент объявляет их серверу, ядро не использует.
