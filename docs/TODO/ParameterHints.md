# Подсказка параметров — попап сигнатуры у каретки

Статус: `[x]` сделано (v1).

Закрывает следующий стаб из [LSP.md](LSP.md) после definition, hover и references:
`languages.registerSignatureHelpProvider` был no-op, и, набирая `greet(`,
пользователь не видел ни списка параметров, ни того, какой из них вводит сейчас.
Калька с VS Code: попап над строкой вызова со строкой сигнатуры, подсвеченным
активным параметром, счётчиком перегрузок `1/2` и описаниями.

## Как устроено

Проводка — калька hover: seam `iSignatureHelpSource` → RPC
`languages.provideSignatureHelp` (таймаут 5000 мс) →
`EditorService.signatureHelpSource`. В отличие от hover/references ответы
провайдеров **не склеиваются**: обходим совпавших по селектору по очереди и
берём первый непустой — так предписывает vscode API («called sequentially until
a provider returns a valid result»), и иначе было бы нечего делать с двумя
разными `activeParameter`.

**Класс-ловушка (та же, что у `CompletionList`).** Конвертер стокового
`vscode-languageclient` конструирует `new code.SignatureHelp()` (без аргументов),
`SignatureInformation`, `ParameterInformation` на каждый ответ, а
`code.SignatureHelpTriggerKind.*` читает на каждом запросе — все четыре
пришлось добавить в стаб `vscodeTypes`. Без них конвертация падала бы целиком, а
единственный след ушёл бы в `client.outputChannel`.

**Триггер-символы объявляет сервер, а не ядро.** `typescript-language-server`
отдаёт `triggerCharacters: ["(", ",", "<"]` и `retriggerCharacters: [")"]`;
клиент передаёт их в регистрацию (объектом-метаданными, если ретриггеры есть, и
rest-строками иначе — поддержаны обе перегрузки), а ядро читает их из
`languages.updateSubscriptions` — тот же канал, что у `.` автодополнения.
Поэтому `<` у дженериков работает бесплатно, а хардкод скобок в ядре не нужен.

**Как подсказка живёт при наборе.** `ParameterHintsService` слушает те же
события, что `CompletionService` (правка взводит флаг, работу делает обработчик
каретки): набор триггер-символа открывает попап, а пока он показан — любая
правка или движение каретки перезапрашивают подсказку (`ContentChange`), и
активный параметр следует за запятыми. Ответ `null` закрывает попап — именно так
его гасит закрывающая скобка. Запросы идут с задержкой 120 мс (`triggerDelayMs`,
как `autoSuggestDelayMs` у suggest), устаревшие ответы отбрасывает счётчик
`requestSeq`. Вставка блока текста подсказку НЕ открывает: триггером считается
именно набор одного символа (общая с автодополнением эвристика
`isSingleCharInsert`).

**Выбранная перегрузка не сбрасывается.** В запрос уезжает эхо показанной
подсказки (`activeSignatureHelp`), и tsserver по нему находит прежнюю сигнатуру
среди новых — иначе следующая же запятая возвращала бы список к первой
перегрузке.

UI — contrib `parameterHints`: `ParameterHintsElement` (рамка, счётчик, метка
сигнатуры с посимвольной подсветкой активного параметра, описания под
разделителем), `ParameterHintsComponent` (overlay-сессия), `ParameterHintsService`
(логика). Метка переносится по словам **со своими офсетами**
(`signatureLayout.ts`): `wrapText` из tuidom схлопывает пробелы, и подсветка
после переноса уехала бы — поэтому кусок строки здесь всегда подстрока исходной
метки. Диапазон активного параметра ищется как в VS Code: пара офсетов берётся
как есть, строковая метка — по границе слова (голый `indexOf` подсветил бы
`name` внутри `nameLength`).

Попап якорится **над** строкой каретки (`offsetY` на свою высоту), потому что
попап автодополнения предпочитает низ: у одной каретки они живут одновременно и
без разведения легли бы друг на друга. Если сверху места нет — уходит вниз.

## Команды

| Команда | Бинд | Что делает |
|---|---|---|
| `editor.action.triggerParameterHints` | Ctrl+K Ctrl+P, Ctrl+Shift+Space | Показать подсказку для вызова под кареткой |
| `showNextParameterHint` / `showPrevParameterHint` | Down / Up (и Alt+Down / Alt+Up) | Следующая/предыдущая перегрузка |
| `closeParameterHints` | Escape | Закрыть попап |

Аккорд Ctrl+K Ctrl+P объявлен основным биндом, а не канонический
Ctrl+Shift+Space: на legacy-tier'е тот неотличим от Ctrl+Space, который уже
занят `triggerSuggest`, — без запасного пути ручной вызов был бы недоступен там,
где терминал не кодирует модификаторы. Канонический бинд объявлен вторым.

Стрелки и Escape перехватываются, только пока попап показан, — и уступают
попапу автодополнения, если открыт и он (`!suggestWidgetVisible` в `when`). В
VS Code тот же порядок задан весами кейбиндов (suggest — EditorContrib+90,
parameter hints — +75).

## Люфты v1

- Описания — плоский текст: markdown-рендерера в tuidom нет (общий люфт с hover),
  стрип общий — `stripMarkdown` из `HoverService`.
- Высота попапа клампится без скролла: очень длинное описание обрезается.
- Мышиного триггера и кликов по стрелкам перегрузок нет (в VS Code есть).
- Отмены RPC нет: таймаут плюс счётчик запросов против устаревших ответов
  (общий люфт с completion, hover и references).
- Пока попап показан, каждая правка и каждое движение каретки — это запрос с
  полным текстом документа (инкрементального sync у нас нет).
- Подсказка и попап автодополнения расходятся по разные стороны каретки только
  в типичном случае: когда сверху нет места, оба оказываются снизу.
