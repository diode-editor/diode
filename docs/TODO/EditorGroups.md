# Editor Groups — сплиты области редактора

Цель: область редактора перестаёт быть одной группой и становится **сеткой групп**
(как в VS Code): каждая группа — свой таб-стрип со своим набором вкладок, своей активной
вкладкой и своим MRU. Разбиение — **только командами и хоткеями**, drag&drop вкладок нет
(мышь участвует ровно двумя жестами: клик, делающий группу активной, и саш между
группами). Работа с группами уезжает в API расширений — значит, раскомментируются
соответствующие куски `vscode.d.ts` (`ViewColumn`, `showTextDocument`, `window.tabGroups`).

Этот документ — **постановка**: пользовательские сценарии (US) и API-сценарии (AS),
плюс номенклатура команд, которая делает сценарии однозначными. Архитектуры и фазировки
здесь нет — планирование реализации идёт отдельным шагом. При реализации каждый US/AS
закрывается e2e-сценарием (по правилам [../PR.md](../PR.md) — фича видимая, значит
сценарий-демо + скриншот обязательны).

## Рамка

**Берём из VS Code:**
- Сетка групп (grid): сплит делит активную группу по вертикали или горизонтали, сплиты
  вкладываются, листья сетки — группы.
- Нумерация групп (`ViewColumn` 1..N) в порядке обхода сетки; закрытие группы схлопывает
  нумерацию.
- Один документ может быть открыт в нескольких группах одновременно.
- Пустая группа существует как самостоятельная сущность (`newGroupRight` и т.п.);
  группа, из которой ушла последняя вкладка, схлопывается.
- Команды и их id — дословно VS Code (`workbench.action.splitEditor`, `focusRightGroup`, …).

**Осознанно НЕ берём (non-goals этой задачи):**
- **Drag&drop вкладок и групп** — разбиение и перенос только командами. Это прямое
  требование постановки, а не упрощение «на потом».
- **Preview-вкладки** (курсив, вытеснение одной вкладкой) — их нет и сейчас; в API
  `Tab.isPreview` всегда `false`, `TextDocumentShowOptions.preview` игнорируется.
- **Pinned-вкладки** — `Tab.isPinned` всегда `false`.
- **Split editor in group** (`workbench.action.splitEditorInGroup` — две вью одного
  документа внутри ОДНОЙ вкладки) — отдельная механика, вне скоупа.
- **Несколько окон** (`ViewColumn` привязан к одному окну) — у нас окно одно.
- **Сплиты нижней Panel и терминала** — панель остаётся одной, под всей сеткой.
- **Webview/notebook-вкладки** в `tabGroups` — их не существует, `TabInput*` покрываем
  только текстом и диффом.

**Что задача обязана вскрыть (известные долги, которые сплит делает видимыми):**
- **Undo на документ, а не на редактор** — [Uri.md](Uri.md), пункт «Сплит-вью и undo».
  Пока editor↔document 1:1, ключ истории per-editor корректен; два редактора на один
  документ обязаны делить историю.
- **Document sync только активного редактора** — [LSP.md](LSP.md), «Осознанные люфты».
  Правка в неактивной группе сейчас не уедет на сервер.
- **Дедуп вкладок глобальный** — `EditorService.openUri` находит вкладку по
  `uri.toString()` во всём списке. С группами дедуп становится **пер-группа**.

## Словарь (чтобы сценарии читались однозначно)

- **Группа** — таб-стрип + контент-слот. Сегодня их ровно одна: `EditorGroupComponent`
  поверх `EditorService` (`src/vs/workbench/browser/parts/editor/`).
- **Сетка (grid)** — дерево рядов/колонок, листья — группы. `Split Editor` делит
  активную группу; `Split Editor Orthogonal` делит её поперёк текущей ориентации.
- **Активная группа** — та, где фокус; если фокус ушёл в сайдбар/панель — последняя
  сфокусированная. Активная группа ровно одна.
- **Активная вкладка** — у каждой группы своя. «Активный редактор воркбенча» =
  активная вкладка активной группы.
- **ViewColumn** — номер группы 1..N в порядке обхода сетки (слева-направо,
  сверху-вниз). Номер — не идентичность: закрыли группу 1 — бывшая 2 стала 1.
- **Документ** — `TextFileModel` на ресурс. Один документ, N редакторов.

## Команды и хоткеи

Id и заголовки — VS Code. Колонка «хоткей» — предлагаемый дефолт; где VS Code дефолта не
имеет, стоит «палитра». Терминальные ограничения — в разделе ниже (US-44…US-46), там же
объяснено, почему у части команд два бинда с `when: tier == …`.

### Разбиение

| id | title | хоткей | when |
|---|---|---|---|
| `workbench.action.splitEditor` | View: Split Editor | `Ctrl+\` | `editorGroupHasEditors` |
| `workbench.action.splitEditorOrthogonal` | View: Split Editor Orthogonal | `Ctrl+K Ctrl+\` | `editorGroupHasEditors` |
| `workbench.action.splitEditorRight` / `Left` / `Up` / `Down` | View: Split Editor Right/… | палитра | `editorGroupHasEditors` |
| `workbench.action.newGroupRight` / `Left` / `Above` / `Below` | View: New Editor Group to the Right/… | палитра | — |
| `explorer.openToSide` | Open to the Side | `Ctrl+Enter` | `filesExplorerFocus` |
| `editor.action.revealDefinitionAside` | Go to Definition to the Side | `Ctrl+K F12` | `textViewFocus` |

`Ctrl+\` = 0x1C (FS) — доходит до приложения на любом tier, включая legacy; это
единственный «сплитовый» бинд, который не нуждается в фолбэке.

### Навигация по группам

| id | title | хоткей | примечание |
|---|---|---|---|
| `workbench.action.focusFirstEditorGroup` … `focusEighthEditorGroup` | View: Focus N-th Editor Group | `Ctrl+1`…`Ctrl+8` (kitty/csi-u), `Ctrl+K 1`…`Ctrl+K 8` (везде) | `Ctrl+6` сейчас занят `openPreviousRecentlyUsedEditorInGroup` — конфликт, см. открытые вопросы |
| `workbench.action.focusLeftGroup` / `RightGroup` / `AboveGroup` / `BelowGroup` | View: Focus Editor Group to the Left/… | `Ctrl+K Ctrl+←/→/↑/↓` | Ctrl+стрелки доходят на всех tier |
| `workbench.action.navigateEditorGroups` | View: Navigate Between Editor Groups | палитра | цикл по кругу |
| `workbench.action.focusActiveEditorGroup` | View: Focus Active Editor Group | палитра | возврат фокуса из панели/сайдбара |

### Перенос вкладок и групп

| id | title | хоткей |
|---|---|---|
| `workbench.action.moveEditorToNextGroup` / `PreviousGroup` | View: Move Editor into Next/Previous Group | `Ctrl+Alt+→` / `Ctrl+Alt+←` (kitty/csi-u), `Ctrl+K →` / `Ctrl+K ←` (везде) |
| `workbench.action.moveEditorToRightGroup` / `Left` / `Above` / `Below` | View: Move Editor into Right/… Group | палитра |
| `workbench.action.moveEditorToFirstGroup` / `LastGroup` | View: Move Editor into First/Last Group | палитра |
| `workbench.action.copyEditorToNextGroup` / `PreviousGroup` | View: Duplicate Editor into Next/Previous Group | палитра |
| `workbench.action.moveActiveEditorGroupLeft` / `Right` / `Up` / `Down` | View: Move Editor Group Left/… | палитра |

### Раскладка и размер

| id | title | хоткей |
|---|---|---|
| `workbench.action.toggleEditorGroupLayout` | View: Toggle Vertical/Horizontal Editor Layout | `Shift+Alt+0` (kitty/csi-u), палитра (везде) |
| `workbench.action.editorLayoutSingle` / `TwoColumns` / `TwoRows` / `ThreeColumns` / `TwoByTwoGrid` | View: Single/Two Columns/… Editor Layout | палитра |
| `workbench.action.joinTwoGroups` | View: Join Editor Group with Next Group | палитра |
| `workbench.action.joinAllGroups` | View: Join All Editor Groups | палитра |
| `workbench.action.evenEditorWidths` | View: Reset Editor Group Sizes | палитра |
| `workbench.action.increaseEditorWidth` / `decreaseEditorWidth` / `increaseEditorHeight` / `decreaseEditorHeight` | View: Increase/Decrease Editor Width/Height | палитра |
| `workbench.action.toggleMaximizeEditorGroup` | View: Toggle Maximize Editor Group | палитра |

Раскладка команд повторяет уже сделанное для сайдбара (`increase/decrease/resetSidebarWidth`
в `layoutActions.ts`): шаг фиксированный, без дефолтных биндов.

### Закрытие

| id | title | хоткей |
|---|---|---|
| `workbench.action.closeEditorsInGroup` | View: Close All Editors in Group | `Ctrl+K W` |
| `workbench.action.closeEditorsAndGroup` | View: Close Editor Group | палитра |
| `workbench.action.closeAllEditors` | View: Close All Editors | `Ctrl+K Ctrl+W` |

`Ctrl+W` (закрыть активную вкладку) остаётся как есть и работает в активной группе.

### Новые when-контексты

`multipleEditorGroups`, `activeEditorGroupEmpty`, `activeEditorGroupIndex`,
`activeEditorGroupLast` — как в VS Code. Существующие `editorGroupHasEditors` и
`editorTabsMultiple` меняют смысл на «в активной группе» (сегодня они про единственную
группу, поэтому смена смысла не ломает существующие биндинги).

## Пользовательские сценарии

### A. Создание сплитов

- **US-1. Split Editor.** Открыт `a.ts`, каретка на строке 40, вид проскроллен. → `Ctrl+\`.
  → Две группы рядом одинаковой ширины, обе показывают `a.ts`; в новой (правой) группе
  каретка и скролл скопированы из исходной; фокус — в правой; статус-бар показывает
  позицию каретки правой группы.
- **US-2. Split пустой области.** Ни одной вкладки. → `Ctrl+\`. → Ничего не происходит
  (команда закрыта `when: editorGroupHasEditors`), сообщения об ошибке нет.
- **US-3. Ортогональный сплит.** Две колонки, фокус в правой. → `Ctrl+K Ctrl+\`. → Правая
  колонка разделилась на два ряда; итог — сетка «колонка | (ряд / ряд)»; фокус в новом
  нижнем ряду; левая колонка не изменила ширину.
- **US-4. Пустая группа.** Открыт `a.ts`. → Палитра → «View: New Editor Group to the
  Right». → Справа появилась группа с пустым таб-стрипом, залитая `editor.background`;
  фокус в ней; статус-бар без позиции каретки/языка/EOL; `Ctrl+P` → выбор файла открывает
  его именно в этой группе.
- **US-5. Open to the Side из Explorer.** Одна группа с `a.ts`, фокус в дереве, курсор на
  `b.ts`. → `Ctrl+Enter`. → Создалась вторая группа справа, в ней открыт `b.ts` и стал
  активным; в левой группе по-прежнему `a.ts`; фокус — в новой группе (не в дереве).
- **US-6. Open to the Side из Quick Open.** `Ctrl+P` → набрать `b.ts` → `Ctrl+Enter`. →
  То же, что US-5; пикер закрылся.
- **US-7. Go to Definition to the Side.** Каретка на символе из другого файла. →
  `Ctrl+K F12`. → Файл определения открылся в соседней группе на нужной строке, исходная
  группа не изменилась.
- **US-8. Не влезает — не делим.** Ширина области редактора 40 колонок, минимальная
  ширина группы 20. → `Ctrl+\` в двухколоночной раскладке. → Сплит не выполняется,
  в статус-баре сообщение «Not enough space to split»; сетка не изменилась.
  *(TUI-специфика: в браузере VS Code просто делает группы уже; в терминале ниже
  порога группа перестаёт быть читаемой.)*

### B. Навигация между группами

- **US-9. Фокус по номеру.** Три группы. → `Ctrl+2`. → Активна вторая группа, фокус в её
  активной вкладке, статус-бар и `editorTabsMultiple` пересчитаны под неё.
- **US-10. Фокус по направлению.** Сетка 2×2, фокус в левом верхнем. → `Ctrl+K Ctrl+→` →
  правый верхний; → `Ctrl+K Ctrl+↓` → правый нижний; → `Ctrl+K Ctrl+→` ещё раз → фокус
  не двигается (справа ничего нет), ошибки нет.
- **US-11. Циклический обход.** Три группы. → «View: Navigate Between Editor Groups» ×3.
  → Фокус обошёл все группы и вернулся в исходную.
- **US-12. Группа помнит своё состояние.** В группе 1 открыт `a.ts` (каретка 100:5), в
  группе 2 — `b.ts`. → `Ctrl+2` → `Ctrl+1`. → В группе 1 активна та же вкладка, каретка
  на 100:5, скролл на месте.
- **US-13. Ctrl+Tab — внутри группы.** В группе 1 три вкладки, в группе 2 — две. →
  Фокус в группе 1, `Ctrl+Tab`. → Переключилась вкладка **внутри группы 1**; вкладки
  группы 2 в MRU-цикле не участвуют.
- **US-14. Мышь делает группу активной.** Фокус в группе 1. → Клик по тексту в группе 2.
  → Группа 2 активна, каретка встала в точку клика. → Клик по вкладке в группе 1. →
  Группа 1 активна, эта вкладка активна.
  *(Ловушка из памяти проекта: координаты клика в e2e абсолютные — брать из `node.box`
  нужной группы, иначе клик уходит в сайдбар.)*

### C. Перенос вкладок и групп

- **US-15. Перенос вкладки вправо.** Группа 1: `a.ts`, `b.ts` (активен `b.ts`); группа 2:
  `c.ts`. → `Ctrl+Alt+→`. → `b.ts` исчез из группы 1 и появился в группе 2 как активная
  вкладка; фокус уехал вместе с ним; в группе 1 активным стал `a.ts`.
- **US-16. Перенос последней вкладки схлопывает группу.** Группа 2 содержит только
  `c.ts`. → Фокус в группе 2 → `Ctrl+Alt+←`. → Группа 2 исчезла, сетка вернулась к одной
  группе; `c.ts` — активная вкладка группы 1; `multipleEditorGroups` = false.
- **US-17. Дублирование вкладки.** Группа 1: `a.ts`. → «View: Duplicate Editor into Next
  Group». → `a.ts` открыт в обеих группах, обе вкладки живут независимо (см. раздел E).
- **US-18. Перенос всей группы.** Сетка «1 | 2», фокус в группе 2. → «View: Move Editor
  Group Left». → Группы поменялись местами; фокус остался в той же группе (теперь она
  первая), её `ViewColumn` стал 1.

### D. Раскладка и размер

- **US-19. Тумблер ориентации.** Две колонки. → «Toggle Vertical/Horizontal Editor
  Layout». → Те же две группы стали двумя рядами, содержимое и активная группа сохранены.
- **US-20. Пресет раскладки.** Открыто 4 файла в одной группе. → «Two by Two Grid
  Editor Layout». → Четыре группы 2×2; вкладки **не** перераспределяются автоматически
  (как в VS Code: пресет меняет только сетку — пустые группы допустимы).
- **US-21. Single схлопывает всё.** Три группы с вкладками. → «Single Editor Layout»
  (эквивалент «Join All Editor Groups»). → Одна группа; вкладки объединены в порядке
  групп, дубликаты одного ресурса схлопнулись в одну вкладку; активной осталась вкладка
  бывшей активной группы.
- **US-22. Ресайз сашем.** Две колонки. → Потянуть саш между ними мышью вправо. →
  Границы поехали, обе группы перерисовались, минимальная ширина соблюдается (саш
  упирается).
- **US-23. Ресайз командой.** → «Increase Editor Width» ×2 → «Reset Editor Group Sizes».
  → Ширина активной группы выросла на фиксированный шаг, потом раскладка выровнялась.
- **US-24. Максимизация.** Сетка 2×2, фокус в правой нижней. → «Toggle Maximize Editor
  Group». → Видна только эта группа со своим таб-стрипом на всю область редактора;
  повторный вызов возвращает сетку в прежних пропорциях.
- **US-25. Ресайз терминала.** Три колонки, окно уменьшено вдвое. → Сетка
  пересчиталась пропорционально; если хоть одна группа ушла ниже минимума — раскладка
  временно схлопывается до влезающего числа групп, а при возврате размера
  восстанавливается. *(Поведение при «не влезает» — открытый вопрос, см. ниже.)*

### E. Один документ в нескольких группах

- **US-26. Правка видна в обеих.** `a.ts` открыт в группах 1 и 2. → Набрать текст в
  группе 1. → В группе 2 тот же текст появился немедленно; каретки независимы (в группе 2
  каретка не прыгнула).
- **US-27. Общий undo.** Правка в группе 1 → фокус в группу 2 → `Ctrl+Z`. → Откатилась
  именно та правка; обе группы показывают откат. *(Закрывает пункт из [Uri.md](Uri.md).)*
- **US-28. Общий маркер изменённости и сохранение.** Правка в группе 1. → Точка «изменён»
  появилась на вкладке `a.ts` в **обеих** группах. → `Ctrl+S` в группе 2. → Файл
  сохранён, точка погасла в обеих.
- **US-29. Закрытие одной из двух вкладок.** `a.ts` изменён и открыт в группах 1 и 2. →
  Закрыть вкладку в группе 2 (`Ctrl+W`). → Диалога подтверждения **нет** (документ ещё
  открыт), вкладка закрылась, правки на месте. → Закрыть вкладку в группе 1. → Диалог
  «Save/Don't Save/Cancel».
- **US-30. Дедуп — пер-группа.** `a.ts` открыт в группе 1, фокус в группе 2. → `Ctrl+P` →
  `a.ts`. → Открылась **вторая** вкладка `a.ts` в группе 2 (а не переключение на группу 1).
  → Повторно `Ctrl+P` → `a.ts` в группе 2. → Переключение на уже открытую вкладку.
- **US-31. Внешнее изменение файла.** `a.ts` открыт в двух группах, файл переписан
  снаружи. → Обе группы показали новое содержимое, скролл каждой сохранён по мере
  возможности.
- **US-32. Read-only.** `a.ts` открыт read-only в группе 1 и обычным в группе 2 —
  **не** поддерживаем: read-only живёт на документе, замок на вкладке виден в обеих
  группах, правки запрещены в обеих. Явно проверяем, что состояния не разъезжаются.

### F. Взаимодействие с остальным воркбенчем

- **US-33. Find внутри группы.** Две группы. → `Ctrl+F` в группе 1 → виджет поиска
  открылся **внутри группы 1** (её `OverlayHostElement`), не перекрывая группу 2. →
  Фокус в группу 2 → `Ctrl+F` → у группы 2 свой виджет со своим запросом; `Escape`
  закрывает виджет только своей группы.
- **US-34. Suggest внутри группы.** Попап автодополнения в узкой правой группе не
  вылезает за её границы (позиционируется от каретки, с отражением влево при нехватке
  места справа).
- **US-35. Статус-бар следует за активной группой.** Позиция каретки, выделение, язык,
  EOL, кодировка, индикатор read-only — пересчитываются при `Ctrl+K Ctrl+→`.
- **US-36. Explorer autoReveal.** `explorer.autoReveal: true`, в группах разные файлы. →
  Переключение активной группы подсвечивает в дереве файл новой активной группы.
- **US-37. Диагностики в обеих группах.** Файл с ошибкой открыт в двух группах →
  squiggle нарисован в обеих; клик по строке в Problems раскрывает файл в **активной**
  группе.
- **US-38. Нижняя панель вне сетки.** `Ctrl+J`. → Панель занимает низ под всей сеткой
  групп (а не внутри активной группы); фокус в панели не меняет активную группу;
  «View: Focus Active Editor Group» возвращает фокус ровно туда, откуда ушли.
- **US-39. Дифф в сплите.** Source Control → активировать изменённый файл при фокусе в
  группе 2. → Дифф-вкладка открылась в группе 2; `Ctrl+6` (alternate editor) работает
  внутри неё.
- **US-40. Output/detached-редакторы не участвуют.** Открытая панель Output не является
  группой, не попадает в `ViewColumn`-нумерацию и не восстанавливается как вкладка.

### G. Сессия

- **US-41. Персист раскладки.** Сетка 2×2, в группах разные файлы, активна группа 3,
  в ней активна вторая вкладка. → Выход и запуск. → Восстановлены: сетка с пропорциями,
  состав и порядок вкладок каждой группы, активная вкладка каждой группы, активная группа.
- **US-42. Пропавший файл.** Один из сохранённых файлов удалён с диска. → Он пропускается;
  если группа осталась пустой — она схлопывается, сетка перестраивается.
- **US-43. Восстановление в маленьком терминале.** Сохранена сетка из трёх колонок,
  запуск в терминале шириной 60. → Раскладка схлопнулась до влезающего числа групп
  (остальные вкладки перенесены в оставшиеся группы), приложение стартовало без ошибок.

### H. Терминальные ограничения и деградация хоткеев

- **US-44. legacy: Ctrl+цифра не доходит.** `terminal.tier: "legacy"`. → `Ctrl+2` →
  ничего (клавиша неотличима от прочего ввода). → `Ctrl+K`, затем `2`. → Фокус во второй
  группе; пока ждём вторую часть чорда, в статус-баре виден хинт `Ctrl+K …`.
- **US-45. kitty/csi-u: работают оба пути.** Тот же сценарий на `tier: kitty` — работают
  и `Ctrl+2`, и `Ctrl+K 2`.
- **US-46. Палитра показывает актуальный шорткат.** «View: Focus Second Editor Group» в
  палитре показывает `Ctrl+2` на kitty и `Ctrl+K 2` на legacy (механика уже есть —
  `keybindingRegistry.lookup`).

### I. Краевые случаи

- **US-47. Последняя вкладка последней группы.** Одна группа, одна вкладка. → `Ctrl+W`. →
  Осталась одна пустая группа (не ноль групп), залитая `editor.background`.
- **US-48. Close All Editors in Group.** Группа 2 с тремя вкладками, одна изменена. →
  `Ctrl+K W` в группе 2. → Диалог по изменённой; после ответа группа схлопнулась, фокус
  перешёл в соседнюю.
- **US-49. Quit с изменениями в разных группах.** `a.ts` изменён и открыт в двух группах,
  `b.ts` изменён в третьей. → `Ctrl+Q`. → **Два** диалога (по числу документов, не
  вкладок); Cancel в любом прерывает выход.
- **US-50. Команда без цели.** Все групповые команды при единственной группе ведут себя
  осмысленно: `focusRightGroup` — ничего, `joinTwoGroups` — ничего,
  `moveEditorToNextGroup` — создаёт группу справа и переносит (как VS Code).

## API-сценарии (расширения)

Общее правило: `ViewColumn` — то, чем расширение адресует группу. Всё, что ниже,
проверяется тестом продюсера (кто и по какому событию шлёт RPC), а не только тем,
что субпроцесс умеет разобрать сообщение — см. «Что считать готово» в AGENTS.md.

### AS-A. Открытие в колонке

- **AS-1. Beside.** `await window.showTextDocument(doc, ViewColumn.Beside)` при одной
  группе. → Создалась вторая группа справа, документ открыт в ней и активен; вернувшийся
  `TextEditor.viewColumn === 2`.
- **AS-2. Явная колонка + опции.** `showTextDocument(uri, { viewColumn: ViewColumn.Two,
  preserveFocus: true, selection: new Range(9,0,9,0) })`. → Документ открыт во второй
  группе, каретка на 10-й строке, **фокус остался** там, где был; активная группа не
  сменилась.
- **AS-3. Active по умолчанию.** `showTextDocument(doc)` без колонки → открытие в
  активной группе (`ViewColumn.Active`).
- **AS-4. Повторное открытие.** `showTextDocument(doc, ViewColumn.Two)` дважды →
  вторая вкладка не заводится, происходит переключение на существующую.
- **AS-5. Колонка за пределами сетки.** `ViewColumn.Three` при двух группах → создаётся
  третья группа (поведение VS Code), а не отказ.

### AS-B. Активный и видимые редакторы

- **AS-6. activeTextEditor следует за активной группой.** Пользователь делает `Ctrl+2` →
  расширение получает `onDidChangeActiveTextEditor` с редактором второй группы;
  `activeTextEditor.document.uri` — файл этой группы.
- **AS-7. visibleTextEditors.** Две группы с разными файлами → `visibleTextEditors.length
  === 2`; один и тот же файл в двух группах → **два разных** `TextEditor` с одним
  `document`.
- **AS-8. onDidChangeVisibleTextEditors.** Событие приходит при: сплите, схлопывании
  группы, смене активной вкладки в **любой** группе, переносе вкладки между группами.
- **AS-9. onDidChangeTextEditorViewColumn.** Перенос вкладки командой
  `moveEditorToNextGroup` → расширение получает событие с новым `viewColumn`.
- **AS-10. Декорации per-editor.** `editor.setDecorations(type, ranges)` в редакторе
  группы 1 не рисует декорации в группе 2 для того же документа (два `TextEditor`).
- **AS-11. Правка в неактивной группе доходит до LSP.** Файл открыт в группах 1 и 2,
  активна группа 1; пользователь правит текст в группе 2 (сделав её активной и вернувшись)
  — сервер получает `didChange` для этого документа. Расширение видит
  `workspace.onDidChangeTextDocument` независимо от того, какая группа активна.
  *(Закрывает люфт из [LSP.md](LSP.md).)*

### AS-C. window.tabGroups

- **AS-12. Снимок групп.** `window.tabGroups.all` при сетке из трёх групп → три
  `TabGroup` с `viewColumn` 1..3, ровно у одной `isActive === true`, у каждой `activeTab`
  и `tabs` в порядке таб-стрипа.
- **AS-13. Тип вкладки.** Обычный файл → `tab.input instanceof TabInputText` с `uri`;
  дифф-вкладка → `TabInputTextDiff` с `original`/`modified`.
- **AS-14. onDidChangeTabs.** Открытие файла → `{ opened: [tab] }`; закрытие →
  `{ closed: [tab] }`; смена активной вкладки или появление «грязного» маркера →
  `{ changed: [tab] }`.
- **AS-15. onDidChangeTabGroups.** Сплит → `{ opened: [group] }`; схлопывание →
  `{ closed: [group] }`; смена активной группы → `{ changed: [group, group] }`.
- **AS-16. Программное закрытие.** `await tabGroups.close(tab)` → вкладка закрыта,
  промис резолвится `true`. Для изменённой вкладки — тот же диалог, что у пользователя;
  отказ пользователя → промис резолвится `false`, вкладка на месте.
- **AS-17. Закрытие группы.** `await tabGroups.close(group)` → все её вкладки закрыты,
  группа схлопнулась, `tabGroups.all.length` уменьшился.
- **AS-18. Неподдерживаемые поля честны.** `tab.isPinned === false` и
  `tab.isPreview === false` всегда; `tab.isDirty` — настоящий.

### AS-D. Команды из расширения

- **AS-19. Групповые команды исполняются через executeCommand.** `await
  commands.executeCommand("workbench.action.splitEditor")` из расширения → сетка
  разделилась ровно как по `Ctrl+\`. Аналогично для `focusRightGroup`,
  `moveEditorToNextGroup`, `joinAllGroups`.
- **AS-20. `vscode.diff` в колонке.** `commands.executeCommand("vscode.diff", left,
  right, title, { viewColumn: ViewColumn.Beside })` → дифф-вкладка открылась в соседней
  группе.

### Что раскомментировать в `vscode.d.ts`

По правилу лок-степа из AGENTS.md — только дословное снятие `// `, ничего не переписывая;
тянет незакомментированный тип — раскомментировать и его либо отложить блок.

| блок | строки (текущий пин) | нужен для |
|---|---|---|
| `enum ViewColumn` | ~11377 | AS-1…AS-5 |
| `interface TextDocumentShowOptions` | ~4863 | AS-2 |
| `TextEditor.viewColumn` | ~5330 | AS-1, AS-9 |
| `window.showTextDocument` (3 перегрузки) | ~15272, ~15282, ~15293 | AS-1…AS-5 |
| `window.onDidChangeVisibleTextEditors` | — | AS-8 |
| `TextEditorViewColumnChangeEvent` + `window.onDidChangeTextEditorViewColumn` | ~14152 | AS-9 |
| `interface Tab`, `TabGroup`, `TabGroups`, `window.tabGroups` | ~23330, ~23411, ~23445 | AS-12…AS-18 |
| `TabInputText`, `TabInputTextDiff` | ~23202 | AS-13 |
| `TabChangeEvent`, `TabGroupChangeEvent` | рядом с `TabGroups` | AS-14, AS-15 |

Блок `Tab.input` в апстриме объявлен юнионом из восьми `TabInput*` (webview, notebook,
terminal, custom) — кандидат на **bounded member-level uncommenting**: раскомментировать
`TabInputText`/`TabInputTextDiff`, остальные оставить в дормантной части, а поле `input`
взять дословно (тип-юнион упомянет несуществующие имена — если так нельзя, блок
откладывается целиком; решается при планировании).

## Решённые вопросы (планирование 2026-08-10)

1. **`Ctrl+6` остаётся за alternate editor.** Дефолтные бинды фокуса групп — только
   до пятой: `Ctrl+1`…`Ctrl+5` (kitty/csi-u) + чорды `Ctrl+K 1`…`Ctrl+K 5` (везде);
   шестая-восьмая — палитра.
2. **Одна ось.** Полоса групп (все колонки или все ряды), тумблер ориентации меняет
   ось всей полосы. `splitEditorOrthogonal` и пресеты сетки (`TwoByTwoGrid`) — вне
   скоупа; `splitEditorUp/Down` в columns-режиме при >1 группе — no-op с логом, при
   единственной группе — смена ориентации и сплит.
3. **Нехватка места: молча не делим, но логируем** через `ILogService`
   (`editorGroups: split refused — not enough space`); всплывающее уведомление —
   отдельной задачей, когда появится механизм нотификаций.
4. **Минимум группы**: 20 колонок × 5 рядов (константы в `EditorPartElement`),
   без пользовательской настройки.
5. **`joinAllGroups`/`Single Layout` схлопывают дубликаты** одного ресурса в одну
   вкладку (инвариант пер-группного дедупа; осознанное отступление от VS Code).
6. **Grid живёт в отдельном `EditorPartElement`** (`tuidom/ui/editorpart/`) со своими
   сашами и весами; вставляется в существующий `setCenterContent`.
7. **Персист**: новый ключ `workbench.editors.groups`
   (`{orientation, groups: [{files, activeIndex}], weights, activeGroup}`,
   `default: null`); при отсутствии — фолбэк на старый `OPEN_EDITORS_STATE`,
   который продолжаем писать плоским снимком активной группы.
8. **Undo на документ — первой фазой этой задачи** (невидимый рефакторинг:
   `TextFileModelRegistry` с ref-count, `UndoManager` переезжает на модель,
   действующая вью — параметр undo/redo, чужие вью ремапятся построчно).

Отступление, найденное на планировании: чорды `Ctrl+K ←/→` для
`moveEditorToNext/PreviousGroup` заняты word-motion-фолбэками на legacy
(`editorActions.ts`) — используем `Ctrl+K Alt+←/→`.

## Фазировка

Каждая фаза шипается отдельно (зелёный CI, без полусделанного видимого поведения):

1. **Общий документ + undo на документ** (невидимая) — US-26…32, дедуп US-49.
2. **Извлечение `EditorGroup` + `EditorPartComponent`** (невидимая, одна группа).
3. **`EditorPartElement` + вторая группа + split/focus** — US-1,2,4,8,9-14,47.
4. **Перенос/join/resize/maximize/ось + openToSide** — US-5,6,7,15-24,48,50.
5. **Find на группу + suggest-позиционирование** — US-33,34.
6. **Персист раскладки** — US-41,42,43.
7. **Полировка**: контекст-ключи `activeEditorGroup*`, верификация US-35…46, доки.

API — двумя фазами: **API-A** (параллельно 1-2): d.ts + runtime-типы, didOpen на
каждое открытие + `editor.didClose` + Map-коалесинг didChange, snapshot-протокол
`editor.layoutChanged` + `editor.showTextDocument/closeTabs/closeGroups` поверх
одногрупповой заглушки, `vscode.diff`; **API-B** (после фазы 3): настоящий
layout-адаптер, ViewColumn-резолв, groupId-таргетинг, полный AS-11.
