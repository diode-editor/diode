# Word Wrap — перенос строк по словам

Статус: **v1 готова** (ветка word-wrap). Здесь — принятые упрощения и follow-up'ы.

## Что сделано (v1)

- Проекция вью (`EditorViewState.buildProjection`) разворачивает логическую строку в ряд на фрагмент: параллельные массивы `{rowDocLine, rowStartOffset, firstRowOfDocLine}`, инвалидация снапшотом эффективной ширины и tabSize. Точки переноса — `computeLineBreakOffsets` (перенос после пробельного прогона, жёсткая резка длинных слов по границе графемы) с инкрементальным `LineBreaksCache` (близнец `LineWidthCache`).
- Ширина вьюпорта пишется в `EditorElement.performLayout` — до render (проекцию читает скроллбар в layout-проходе); смена ширины дозаказывает кадр отложенным `markDirty`.
- Рендер режет строку «колоночным окном» фрагмента (один `DisplayLine` на строку за кадр); продолжения не повторяют номер строки, chevron, change-bar и маркеры; indent guides — только на первых фрагментах; `contentWidth = viewportWidth` (горизонтальный скроллбар гаснет), `scrollLeft ≡ 0` клампится в сеттере.
- Навигация по РЯДАМ вью: `stepPositionVertically` (липкая колонка относительно начала фрагмента), Home → начало фрагмента, End → последняя графема не-последнего фрагмента; reveal — по ряду каретки; мышь клампится к фрагменту.
- Настройки `editor.wordWrap` (`off|on|wordWrapColumn|bounded`) и `editor.wordWrapColumn`; `View: Toggle Word Wrap` (Alt+Z) — transient session-override поверх конфига.

## Осознанно НЕ сделано (follow-up'ы)

- [ ] **`editor.wrappingIndent`** (none | same | indent) — продолжения всегда начинаются с колонки 0. Потянет за собой сдвиг колоночного окна в рендере, хит-тестах и `viewLineStartColumn`.
- [ ] **Wrap в дифф-редакторе** — стороны выравниваются по view-строкам через зоны, перенос развёл бы половины; `TextEditorPane.wordWrapForcedOff` форсит off (упомянуто и в [DiffViewer.md](DiffViewer.md)). Честная реализация должна синхронизировать высоты перенесённых строк зонами.
- [ ] **Cursor affinity** — offset на границе фрагментов всегда маппится на следующий ряд; End на не-последнем фрагменте ставит каретку перед break-пробелом (`end − 1`), а не на визуальный конец ряда. VS Code решает это парой позиция+affinity.
- [ ] **Честный `wordWrapColumn > viewportWidth`** — v1 клампит колонку к вьюпорту (режим эффективно = bounded): перенос за правым краем потребовал бы горизонтальный скролл при активном wrap, а v1 живёт инвариантом `scrollLeft ≡ 0`.
- [ ] **Персист Alt+Z** — session-global override, не пишется в settings.json и не помнит per-resource (VS Code хранит transient state на ресурс).
- [ ] **`wordWrapBreakBefore/AfterCharacters`** — точки переноса только whitespace + жёсткая резка; CJK-текст без пробелов режется по графемам, пунктуация не переносится.
- [ ] **Стабилизация вертикального скроллбара** — на документе, влезающем ровно на границе ±1 колонки, теоретически возможен редкий флип «полоса ⇄ без полосы» (решение о полосе принимается по проекции прошлой ширины и дозаказ кадра сходится, но у VS Code есть отдельная механика стабилизации).
